二、改成从近到远的连续多行追踪

不再仅依靠两个很窄的扫描带及 bottom lock 点的合并拟合来确定航向角。

在鸟瞰图的近端到中近端，设置一段连续扫描区域，从图像下方向上方逐行采样。范围、行距集中配置，不要散落硬编码。

对于 320×400 鸟瞰图，可以先以 y≈390 到 y≈220、每隔约 10～12 像素作为初始范围；这是可调整的初值，不是硬性要求。必须确认循环实际覆盖整个配置范围，不能名义上扫描几十行高度，实际上因 max_rows 提前退出只取开头一小段。

复用现有逐行 run 提取逻辑，注意现有预处理图的前景极性，不要误把“黑线在二值图中为白色”当成背景。

分别追踪 left_x(y)、right_x(y)，再计算 center_x(y)：
- 近端可靠观测作为追踪起点。
- 后续行使用已接受的邻近行边界位置、局部趋势预测搜索窗口。
- 上一帧的边界轨迹可以辅助搜索，但不能覆盖当前可靠观测。
- 配对需要检查左右顺序、线宽、赛道宽度、位置连续性。
- 不能简单取整行最左和最右的黑线，也不能按图像中轴判断左右身份。
  弯道或横向偏移时，两条边界可能同时位于图像中轴同一侧。

每个采样行保留边界坐标、中心坐标、点来源、置信度及有效状态。
真实双边观测、单边推算、缺口预测必须能够区分。

三、补偿机制

1. 双边均可信
   center_x = (left_x + right_x) / 2。
   只有可信的真实双边观测，才能更新局部赛道宽度估计。

2. 只有单边可信
   根据已经建立的左右边界身份，使用最近可信宽度推算中心：
   左边界存在：center_x = left_x + width / 2。
   右边界存在：center_x = right_x - width / 2。

   此处 width 是对应局部扫描行的横向边界间距，不要未经转换就把
   赛道法向物理宽度当成横向间距。允许真实宽度随位置变化。
   补偿点权重低于双边实测点；单边身份不明或宽度先验不可信时，拒绝推算。

3. 两边都缺失
   只允许对短缺口进行有限插值或外推，并标为预测点。
   预测点不能反过来更新宽度，也不能被当成新增实测证据。
   不要无限延伸轨迹，不要把超出画面的预测坐标 clamp 到画面边缘，
   再将其作为真实点参与拟合。

上一帧信息主要用于搜索先验。连续丢失后应过期并重新捕获，不能靠历史预测一直维持“检测有效”。

四、在物理坐标中拟合航向角

使用现有鸟瞰像素到地面坐标的转换，将可靠中心点转换为：
X：横向，向右为正。
Z：前向，向前为正。

第一版优先使用稳健加权直线拟合：
X = b + k * (Z - Z_ref)

内部定义：
heading_right_deg = degrees(atan(k))
即沿前进方向向右延伸为正，向左为负。

不要直接对像素斜率取 atan：
鸟瞰图的横纵像素物理尺度可能不同，而且图像 y 向下增大、
地面 Z 向前增大，方向相反。

必须检查现有 heading_deg 和 debug["angle_err_deg"] 的符号约定。
若旧接口采用 atan(dx/dy * 横纵尺度比)，它与上述内部定义符号相反，
应在输出适配层显式转换，并通过测试证明。
不要为了统一内部定义，顺手修改下游控制器的符号。

航向估计使用明确的近端参考区间，避免远处弯道过度影响近端方向。
第一版不需要新增曲率控制或高阶曲线模型。

拟合要求：
- 双边实测点权重最高，单边补偿点较低，预测点更低或不参与拟合。
- 使用轻量稳健处理抑制离群点，例如残差筛选或 Huber 迭代。
- 检查有效点数、真实观测支持、纵向跨度和拟合残差。
- 不能仅凭几个挤在相邻行上的点就给出高置信度航向。
- 同一个点不要因来自不同数据容器而重复计权。
- 不要因为中心线偏离图像中轴，就降低真实边界的可信度。
