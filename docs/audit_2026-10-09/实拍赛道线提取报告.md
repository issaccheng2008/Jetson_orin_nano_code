## 二、旧算法为何能把肉眼可见的线删掉

旧流程在鸟瞰灰度上先做31×31 black-hat，然后：

1. Gaussian31、C=-12仅生成阈值候选。
2. 取候选响应的中位数减12，得到一个全局阈值；不足100候选时采用原有抽样Otsu减12。
3. 将阈值固定限制到25～80，再用它重新二值化。
4. 闭5 → 开5 → 闭5 → 开3。
5. 删除面积<300 **或竖向高度<80** 的连通域。

暗画面中固定12和25门槛不会随对比度缩小；细线还可能被开运算消掉。弯道接近横向时即使很长，也可能因为高度不足80被整段删除。光照或抖动造成的短断片也容易被面积门槛删掉。

具体例子：新录像40.2秒，black-hat最大响应60，自适应候选仅150像素，最终二值图为空。不能把这种情况全部归因为执行器、控制参数或模型，因为赛道信息在控制器之前就已被删除。

对所有灰度乘2.4再走旧流程，最新标注覆盖仅从85.8%变86.0%，旧录像的覆盖则从36.8%降到5.1%：较亮区域被截断到255，原有黑线/地板差异消失。统一匹配画面平均亮度并不能解决提取问题。

## 三、当前实现

实现文件：`new_vision/jetson/line_preprocess.py`；接入位置：`LineDetector.process()` 的鸟瞰灰度之后、车道采样之前。

```text
原始BGR → 原透视映射 → 最大颜色通道灰度
        → CLAHE限幅局部增强（clipLimit=2，8×8网格）
        → black-hat31 → 原阈值选择（25～80）
        → 闭5 → 闭5
        → 连通域面积≥48 且 max(宽,高)≥24
        → 原车道采样、几何配对、分段观测、转向控制
```

- CLAHE对不同亮度的小区域分别增强，限制对比度放大，避免直接把整张画面乘成白色。
- 删除5×5、3×3开运算，保住已增强的细线；保留闭运算，只连接小尺度断裂，不能补出被脚遮住或反光抹掉的整段线。
- 用长边而非竖向高度筛片段，容许斜线和横向弯道。较小连通域阈值提高候选覆盖，同时带来更多刻度/边缘候选。
- 图卡、红条及原灰度质心兜底继续读取原有画面；CLAHE只用于巡线候选。所有坐标、相机几何及控制器含义保持原有实现。
- `legacy`保留原阈值、开闭运算、面积/高度过滤。冻结旧源码的对照测试确认其既有输出兼容。

新增每帧标量进入现有 `line_frames.jsonl` 的 `measurement`：

| 字段 | 意义 |
|---|---|
| `preprocess_mode` | 本趟实际使用contrast或legacy |
| `preprocess_gray_mean/std` | 鸟瞰原最大通道灰度的均值/标准差；与上面BGR2GRAY统计定义不同 |
| `preprocess_threshold_pixels` | 全局二值化后前景数量 |
| `preprocess_morph_pixels` | 形态学之后前景数量 |
| `preprocess_foreground_pixels` | 连通域过滤后候选数量 |
| `preprocess_components` | 留下的连通域数量 |

原有 `black_th` 仍记录实际阈值。新模块的SHA256加入运行清单；便于判断线在哪一步消失，不能把像素多直接解释为识别准。

方法依据：[OpenCV CLAHE](https://docs.opencv.org/4.x/d5/daf/tutorial_py_histogram_equalization.html)、[形态学运算](https://docs.opencv.org/4.x/d9/d61/tutorial_py_morphological_ops.html)、[自适应阈值](https://docs.opencv.org/4.x/d7/d4d/tutorial_py_thresholding.html)。本项目的组合、固定参数及筛选条件是工程选择，效果由下述实拍评估检验。

## 四、真实线覆盖与误检的独立评价

在17张固定画面上，由独立子代理只看原始帧和鸟瞰RGB，按坐标网格标记可见赛道线中心，不查看候选/二值输出。14张可评价，共27段可见线。遮挡、非场地区域及不确定区域屏蔽；卡片框、刻度、场地外轮廓在可辨认地面区域中作为负例。中心位置估计误差约2～4个鸟瞰像素；标注仍需人类复核，不能作为仪器测量的精确线宽真值。

指标：中心线点到二值候选≤4px计覆盖；候选像素到标注中心线≤10px计容差精度；忽略区域不评分。统计按像素加权。容差会包容胶带宽度和标注误差，因此不能把精度叫作逐像素分割准确率。

| 画面组 | 数量 | 旧版中心覆盖 | 新版中心覆盖 | 旧版容差精度 | 新版容差精度 |
|---|---:|---:|---:|---:|---:|
| 新录像 | 7 | 85.8% | **95.5%** | 99.0% | **88.7%** |
| 四份旧录像 | 7 | 36.8% | **94.9%** | 100.0% | **94.7%** |
| 合计 | 14 | 61.1% | **95.2%** | 99.2% | **91.4%** |
| 前段诊断子集 | 7 | 65.6% | 93.3% | 98.9% | 90.9% |
| 后段诊断子集 | 7 | 54.0% | 98.1% | 100.0% | 92.2% |

前/后段来自相同录像，研发时比较过双方候选结果，不是严格独立盲测。标注复核冻结后重算全部结果，不能用早期未复核坐标的探索分数。

并非每帧都提高：新录像13.4秒，覆盖94.8%→85.8%；CLAHE后的局部响应仍可能在全局阈值阶段丢掉部分弱线。26.8/93.9/107.3秒还多提取了部分刻度或轮廓。下一步若需要进一步降低误检，应利用连续边界的方向、宽度、邻接与历史身份，不能再用统一的竖向高度过滤。

**严重模糊/遮挡压力画面：** 新录像40.2秒、120.7秒及旧18_11_50第41帧，不具备可靠中心线真值，单列查看，未计入95.2%。算法不能从完全丢失的图像信息中恢复真实路径。

标注：[annotations.json](line_extraction/annotations.json)；逐帧得分：[annotated_scores.csv](line_extraction/annotated_scores.csv)；版本与汇总：[report.json](line_extraction/report.json)。

## 六、复现

在有OpenCV4.x和NumPy的环境中，仓库根目录执行。这里实测OpenCV4.14.0、NumPy2.5.3；不修改生产依赖。Windows环境把路径改为原来的 `D:\用户\Lenovo\桌面\Robocup` 即可。

```bash
python scripts/measure_lane_video_photometry.py \
  --data-dir '/mnt/d/用户/Lenovo/桌面/Robocup' \
  --output /tmp/lane-photometry

python scripts/evaluate_lane_extraction.py \
  --data-dir '/mnt/d/用户/Lenovo/桌面/Robocup' \
  --output /tmp/lane-extraction --replay

PYTHONPATH=new_vision/jetson:tests:humanoid_jetson_deploy \
  python -m unittest test_line_preprocess test_line_geometry_p1 \
  test_line_ground_heading test_lane_segments test_line_state_snapshot \
```

脚本只读录像，不打开摄像头、串口、电机或运行模型。亮度脚本的人工排除表只适用于这五份已审查录像，不可原样套用于其他录像。评价脚本输出17张对照图、逐帧标注得分、汇总；`--replay`额外输出完整逐帧CSV。源文件和标注哈希随报告保存。

### 当前能确认和仍需验证的边界

已有实拍证明：旧预处理确实删除可见线，新版对这批可辨认画面的提取有改善。尚不能确认：极端抖动/反光下的准确率、全视频边界身份准确率，以及新版真实闭环是否更稳。这些都需要新录像或实车验证。此次不更改相机硬件值，避免将亮度匹配误当作提取修复；也不取消几何质量检查去换取更多“valid”。
