# 图卡精准与模糊识别改进及实拍验证

2026-10-09，发布分支 `policy49flitter-vi`。本文区分已取得的离线改善与剩余实车问题。

## 1. 精准识别：先保留原灰度，再分离框与图形

原找框、地面几何验证仍决定哪个四边形是图卡。找到合格框后新增 `card_appearance.py`：

1. 对完整卡片原灰度作透视矫正，线性插值，保留外框和内部图形。
2. 在卡片局部用 Otsu 分割墨迹，避免整幅地板的亮度分布决定卡内门槛。
3. 使用墨迹/纸面嵌套轮廓区分外框、纸面和内部图形。轮廓层次的奇偶性也用于避免把纸面洞再次当墨框。
4. 对闭合的内图形轮廓沿用既有六类分类规则。部分断外框或图形粘框时，只有独立、居中的闭合内孔才可作为描边图形的证据；证据不足则回退旧图形提取。

**修复的具体问题**：旧方法先二值化再矫正，并固定裁去外侧14%，会截掉贴近框的三角下边；开放轮廓的面积/凸包比随之异常，三角会误入星形、十字等分支。保留完整局部灰度和闭合轮廓后，不再依赖这种裁边猜测。

[三角卡四列对照](card_recognition/appearance_demo/WIN_20260922_20_32_48_Pro.png)：原图、旧裁边二值、完整原灰度矫正、新二值与实际分类轮廓。该原照片旧路径判为星形，新路径判为三角。

|---|---:|---:|
| 31张六类原实拍 | 27 / 0 | **28 / 0** |
| 同31张人工增益0.6 | 26 / 2 | **28 / 0** |

原来识别正确的27张均保留。增益试验是同帧反事实，不是另采集的暗光实车。11张三角仍有5张未识别，主要剩余找框/几何拒绝，不能宣称精准链全部解决。

## 2. 模糊识别：有限断边修复，在卡平面量结构

旧闭合环 cue 成功时保持其位置和分数。仅当旧 cue 无候选或低分时，新 `card_presence.py` 尝试补充：

1. 两种黑帽尺度与四组门槛/闭运算提出有限断边候选；同核黑帽及膨胀支持图缓存复用。
2. 候选四边回到**未修复墨迹**验证：每边支持率≥40%，平均≥70%，最长缺口≤边长35%。修复跨度也受短边35%限制。
3. 将四边形矫正到96×96卡平面，测纸面与内部标记。不能在轴对齐外接框中测“纸面占比”：旋转或透视卡天然只占其外接框的一部分；轴向腐蚀也会削掉真正内部图形。这是第一版仍漏检的结构原因。
4. 卡平面要求纸面≥30%、内部墨占核心2.5%～75%、内部明暗差≥20参考灰度单位；纸面亮度门槛仍按既有均值/标准差归一化。新弱结构通道分数至少3，旧闭合环出口仍是1.2。
5. 保留原时间确认，累计合格命中后才报 presence；**当前命中**才能提供新位置，未命中帧不继承旧框位置。

这个通道只证明“有卡”，不提供类别，也不投票。暗化补偿以原灰度和既有标准化单位计算，不修改原画面。仍要求候选完整处于图中；整边被遮挡或裁掉时不会靠大块反光补猜。

### 连续实拍验收

采用9段有卡区间共80次调用、7段无卡区间共167次调用；每3源帧检测一次。每个正例调用单独人工标卡框，避免关键帧线性插值跟不上步态摇晃。旧插值产生的“24/80定位”已经撤回。

| 指标 | 基线 `c7ad975` | 最终集成版 |
|---|---:|---:|
| 原始presence调用数 | 40 | 48 |
| presence位置匹配真实卡 | 35 | **44** |
| 精准框匹配并正确分类 | 6 | 6 |
| 视频精准错类 | 0 | 0 |
| 167无卡调用cue过闸 / presence | 0 / 0 | **0 / 0** |
| 9次有卡遭遇中至少定位一次 | 8 | 8 |

新增9次真实定位：两段星形运动录像各4次，以及暗版方卡1次；旧正确定位没有丢失。两段星形第一次确认各提前12个保存视频帧，约0.60秒；这不是实车停车提前量，录像帧率、检测周期和现场运动不同。

另用背景反光图片和3张历史无卡失败照片，加上167视频负例，共171个负例，原图/暗化0.4/横向11像素模糊/纵向11像素模糊四种条件均无新增候选。参数是在这批共享开发数据上选定，没有独立未见过的测试集；四种变换不能作为684次独立实车试验。

**剩余漏检**：暗版 `new_circle_restart` 仍0/4，卡外框与视频底部HUD相连或被裁边，无法获得完整支持；第一张卡的QR、首卡锁存、后两卡的接近触发机制也需要真正实车验证，离线识别改善不能证明它们的停车距离。

## 3. 接口、日志和复现

六类动作映射、停车后发送7、等待DONE与0.1秒稳头、投票规则、动作后3秒恢复行走，以及Nano/STM32通信均保持既有契约。此次没有把模糊候选直接作为动作或类别。

逐帧 `line_frames.jsonl` 新增：

- `card_shape_classification_path`、`card_shape_appearance_reason/contrast/threshold`：精准提取来源及失败原因。
- `card_cue_presence_path`：旧闭合环或新断边通道；`card_cue_broken_*`：候选数、拒绝阶段、四边/内部支持、参考与原始分数。
- `card_shape_preprocess_ms`、`proposals_ms`、`verification_ms`、`classify_ms`、`presence_ms`、`total_ms`：各阶段耗时。字段完整前缀为 `card_shape_`；只在实际检测帧写入。
- 启动清单新增两个模块的源码哈希。

[逐帧人工GT和独立比较](card_recognition/report.md)、[最终数据](card_recognition/comparison_final.json)含真实相机配置哈希、源码哈希、逐调用结果和原图接触表。快照验证必须同时包含 `new_vision/config`，否则相机距离标定会悄悄回退，造成错误比较。

```bash
python scripts/evaluate_card_sequences.py \
  --annotations docs/audit_2026-10-09/card_recognition/reviewed_annotations.json \
  --ref current --save-gt-sheets \
  --output /tmp/card-final-validation
```

未连接实车做行走验证。桌面CPU耗时只能用于定位计算热点，不作为Nano实时频率承诺；新增断边模块单独中位约5.1ms、P95约9.9ms，应在板子上检查整链延迟和关节命令流是否保持独立稳定。
