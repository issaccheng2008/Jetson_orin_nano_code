# 三次图卡动作完成后继续巡线

`run_policy_vision.py` 在每次启动时从零累计成功完成的图卡动作。启动门控中识别并执行的首卡也计入，所以正常比赛流程是首卡加后续两张图卡。

只有成功分类后发送的动作事件收到匹配的 `action_id` 和 `action_done=true` 才计数。同一事件只计一次；识别失败、投票不足、平票、重摆或恢复姿态不消耗次数。首卡的完成反馈即使晚于其停车计时结束，仍可计入。

累计达到 3 次后，本次进程跳过图卡存在检测、近距停车判断和图形分类，即使继续看到图卡也不会因此停车。第三次动作仍按原流程完成最短保持和姿态恢复，然后继续巡线。重新启动视觉进程会重新计数。

控制台会输出完成进度和关闭图卡检测的提示。启用视觉日志时，`line_frames.jsonl` 同时记录 `card_completed_count`、`card_completion_limit`、`card_detection_enabled`。

本次部署保留 Jetson 原有的未提交调参 `CardFlow.VOTE_SECONDS = 2`；GitHub 中的默认窗口仍为 1 秒。该调参不改变上述完成计数。

验证使用独立临时目录中的模拟相机和动作反馈，未启动真实机器人动作。图卡回归覆盖首卡计数、延迟反馈、失败不计数、未知和重复完成反馈，以及第三次动作的最短保持。
