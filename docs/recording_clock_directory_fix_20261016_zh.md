# 开机未校时导致日志固定在 clock_unsynced（2026-10-16）

Jetson 多次在开机约 16–49 秒时以 1970 年时间创建测试会话。`create_session()` 只在开始时选择一次
目录；网络校时随后成功，已打开的视觉、录像和策略日志仍写进最初的 `clock_unsynced/test_boot_*`。
这也是同一目录出现 1970 年文件名和正常日期控制日志的原因。

修复后，创建测试目录前最多等待 60 秒，直到系统日期至少达到部署年份 2026。日期仍无效就抛出异常，
不创建任何测试目录、不启动策略控制；systemd 按原有 `Restart=on-failure` 重试。
有效时间可来自 RTC、systemd 保存的时间或网络校时，不额外强制依赖网络 NTP。
年份检查只排除明显的 1970 年启动时间，不能独立证明日历时间的精度。

安装脚本为视觉服务添加 `Wants=time-set.target` 和对应启动顺序，先让系统恢复保存的时间。
只设置 `After=network.target` 并不能保证系统日期已恢复。

回归测试覆盖：先恢复日期再创建目录、60 秒超时不留下半成品、可再次重试、控制器不在校时失败时
初始化、历史数据保留、视觉/控制/电机日志归于同一会话，以及 systemd 单元启动顺序。

历史归档按原始视觉帧中已经恢复正常的 `host_time_ns` 确认日期。整目录移动、保留原 test_id 和原始
时间戳，另保存映射与校验清单；不能把校时前的原始时间戳伪造成已校时数据。没有任何可靠日期的
会话继续保留在 `clock_unsynced`，避免猜测归档日期。
