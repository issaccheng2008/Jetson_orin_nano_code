# CPU优化与相机并行采集

分支：policy49flitter-vi。日期：2026-10-10。

## 使用

终端B沿用原命令，默认已经启用异步采集。可显式指定：

```bash
python -u new_vision/jetson/run_policy_vision.py [原有参数] --camera-async
```

`[原有参数]`是说明占位，执行时替换成实际参数。需要恢复串联采集做对照时加`--no-camera-async`。按钮启动脚本不必修改，默认生效。A/C与STM32协议保持原样，不启用GPU，不更改控制档位、曝光和白平衡。

## 处理结构

```text
相机 → 采集线程不断read → 一个最新帧槽 → 处理线程：巡线/图卡/决策/UDP
                             ↑
                     新帧覆盖尚未处理的旧帧
```

不使用无限队列，不在多个线程同时读同一VideoCapture。取走的帧独立拥有像素内存，采集继续不会覆盖处理中的图。无新帧最多等0.25秒，不重复处理同一帧；读取失败清空旧槽，现有失败分支发送零速度。退出由采集线程释放相机，避免read与release跨线程竞态；若驱动阻塞超过退出等待1秒，记录提示，由daemon线程在read返回后释放。

本机采集返回时刻并非传感器曝光时间。驱动内部缓冲仍可能引入延迟，本实现持续读取以减少积压，不声称已测到真实曝光到控制端的完整延迟。

停车后的图卡稳定等待按本帧采集read开始时间判断，早于倾身完成/稳定截止时间的帧不参与本次识别和投票。原有停车、启动、图卡动作与命令保持策略保留。

## CPU修改

- `np.max(BGR,axis=2)`改为OpenCV通道最大值，普通uint8 BGR逐像素等价。
- 亮度映射`lut[image]`改为`cv2.LUT`，沿用完全相同的256项LUT、舍入和裁剪；保留单通道三维数组等形状语义。巡线、图卡共用函数均受益。
- 移除鸟瞰灰度中被maxRGB覆盖的标准加权灰度计算。
- 掩膜Gaussian权重分母按mask内容、尺寸和核参数缓存；即使mask原地修改也会失效，最多4项。
- CLAHE插值坐标缓存，分32行处理，减少全图float64临时数组；保持原运算顺序与舍入，未换成不支持掩膜的普通CLAHE。
- 掩膜膨胀/腐蚀减少重复where及类型转换，维持无效区中性填充值。

没有修改图卡候选门槛或降低识别频率。剩余形态学、CLAHE的进一步提速需要专门实现和对照，不能把所有GPU算子强制打开。

### 回归

347项相关测试通过；最终LUT形状、异步入口与segments集成共10项复核通过（包含重复测试）。覆盖mask变化缓存失效、随机/极端亮度逐像素等价、最新帧替换、断流清旧帧、不重复消费、超时、释放与实际视觉入口遥测。同步时序mock测试明确使用`--no-camera-async`；真实异步线程有独立测试覆盖。

## 新遥测字段

都写入`records/tests/<日期>/<test>/vision/run_*/line_frames.jsonl`：

- `camera_async`：采集模式。
- `camera_sequence`：采集线程成功读取序号；视觉frame仍是已处理帧号。
- `camera_capture_read_ms`：采集线程read耗时（包含等待与解码）。
- `camera_capture_period_ms`：最近两个采集返回的间隔。
- `camera_capture_period_count/mean_ms/std_ms`：累计采集间隔统计，不因处理跳帧漏掉采集样本。
- `camera_capture_elapsed_s`：从第一帧成功读取起的时间。
- `camera_frame_age_ms`：采集返回到处理取帧的等待时间，不含后续处理。
- `camera_frames_skipped`、`camera_frames_overwritten`：本次跳过帧数、累计未消费覆盖数。
- `camera_return_to_publish_ms`：采集返回到此次命令发布的延迟。
- 原`camera_read_ms`在异步模式下是处理线程取帧等待耗时；不能与旧同步read耗时直接等同。
- `loop_period_ms`、`line_process_ms`、`shape_update_ms`继续代表处理循环与阶段。

采集30Hz而处理8Hz是允许的：约22帧/秒主动丢弃以保留新鲜观测，不是积压后慢慢处理。要让最终控制观测达到15～20Hz，还需把每次完整处理压到约50～67ms；单纯并行读帧无法消除计算耗时。
