# policy49flitter → policy49flitter-vi 同步

来源：`origin/policy49flitter` 的 `44cf839`。目标分支：`policy49flitter-vi`，以合并提交保留双方历史。

## 本次同步

- `--video-source bird_pair|binary|camera`：默认鸟瞰彩色图与最终巡线二值图并列；支持切回原始摄像头或单独二值图。
- 录像下方显示 VISION 和 ROBOT CMD：前者为视觉发布指令，后者为主程序模型保持/接管及串口发送后的指令反馈，并非测得的真实机身速度。反馈缺失、过期、未发送或电机未使能时会标明状态。
- 视频按时间戳重采样，缺帧会重复前帧；播放FPS不等于摄像头实际采集FPS。逐帧JSONL保留来源帧、命令及时间。
- 同步逐阶段耗时、边线候选/配对/几何门槛拒绝原因、转向角度档位配置、近远观察区域配置和指令窗口滤波，以及相应命令文档。
- 同步来源分支对旧生成媒体的清理；本分支10月10日鸟瞰修复资料保留。

## 本分支兼容处理

保留等比例鸟瞰、无效地面掩膜、已放宽的跳变阈值及本分支的legacy提线+输入归一化默认方式。来源分支的近观察区默认像素回退迁移到新的地面坐标，不会重新使用旧350～399行语义。

录像跟随实际623×400鸟瞰比例，左右画面等比缩放，下方另加HUD；不再将鸟瞰压成320×400。增加实际MJPG编码、解码测试，确认方形标记长宽比保持。

原有未提交GPU/模型/图卡工作先备份，再恢复到工作区，不混入这次合并提交。

## 录制命令参数

在原视觉启动命令后加：

```bash
--recording-root records/tests \
--record-video --video-source bird_pair --video-fps 10 --video-width 960
```

切换画面只需更换 `--video-source camera` 或 `--video-source binary`。关闭录制用 `--no-record-video`。未设置 `--recording-root` 时，不会创建统一录制会话。

输出位于 `records/tests/日期/test_*/video/`：

- `camera_commands.avi`：录像，文件名在三种源模式下相同。
- `frames.jsonl`：逐帧时间与指令索引。
- `manifest.json`：画面源、编码尺寸、帧数、丢弃样本及异常信息。

要显示 ROBOT CMD，终端C也需使用同步后的同一分支，以发布执行命令反馈。
