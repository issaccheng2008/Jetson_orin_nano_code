# 巡线曝光、二值化和转向选档

检查日期：2026-10-09；本地分支 policy49flitter-vi。以下描述源码，不代表板子当前使用相同参数或已完成实车验证。

## 曝光和 C 的关系

巡线检测实际经过：

1. 透视映射到320×400；灰度主要取每个像素最大的颜色通道。
2. 31×31 black-hat：形态学闭运算减原图，把窄的暗赛道线变成亮响应。
3. 对 black-hat 响应进行 Gaussian 自适应阈值，blockSize=31、C=-12。
4. 自适应候选像素多于100时，取候选响应中位数减12；否则用 Otsu 阈值减12。阈值再限制到25～80。
5. 用第4步的全局阈值清理 black-hat，做开闭运算，再删除面积小于300或高度小于80像素的连通域。

因此最终检测输入不是直接使用第3步的自适应二值图。后面的全局阈值和连通域筛选也可能使弱、断裂或接近横向的赛道线消失。

OpenCV 的 THRESH_BINARY 判定是 `响应 > 局部高斯加权均值 - C`。C=-12 要求响应比局部均值高约12。C 改为-6会放宽，改为-20会收紧；它没有按局部标准差归一化。[OpenCV 官方说明](https://docs.opencv.org/4.13.0/d7/d4d/tutorial_py_thresholding.html)

理想的不截断、整体减去固定亮度，在 black-hat 的差分中会抵消；整体乘以较小系数则会缩小 black-hat 响应和局部对比度，而固定的12及25下限不随之缩小。例如原来的局部响应差18大于12，缩小一半到9后便无法通过。这是数学推断，真实相机还受伽马、增益、噪声和像素截断影响。

全图方差下降不必然导致丢线：去掉背景噪声也可能让方差下降。需要看赛道附近的响应分布和线/地板分离程度。白平衡改变各颜色通道，不等于只降低总体亮度；当前最大通道灰度会受到这种变化影响。短曝光能减少运动模糊，但也可能降低暗处的绝对对比度。

在本机 OpenCV 5.0 的合成图上做了上述阈值步骤对照：320×400、地板灰度200、两条宽7像素且灰度140的竖线。以下不包含最终连通域筛选，不是实车准确率。

| 输入 | C | black-hat最大响应 | 自适应候选像素 | 全局阈值 | 全局保留像素 |
|---|---:|---:|---:|---:|---:|
| 原图 | -12 | 60 | 5600 | 48 | 5600 |
| 所有灰度减30 | -12 | 60 | 5600 | 48 | 5600 |
| 所有灰度乘0.25 | -12 | 15 | 0 | 25 | 0 |
| 所有灰度乘0.25 | -6 | 15 | 5600 | 25 | 0 |

这里放宽 C 恢复了候选，但25下限依然删除所有线响应，说明两个环节必须分别检查。

建议先同时保存原图、black-hat、自适应候选、全局清理后的图，记录 black_th、候选数量及近/中/远段有效像素。用同一组实拍分别检查 C 与25下限；只调整 C 无法保证弱线穿过后续筛选。当前相机示例配置的曝光、白平衡模式均是 keep；不能仅根据新增了控制接口就判定它们已经让画面变暗。本次不改曝光、C或阈值下限。

## 当前转向计算

正方向表示几何左转。heading 模式使用近处横向位置 near、其深度 z_near、赛道方向 theta，计算前视深度 L 的目标：

```text
x_target = near - (L - z_near) * tan(theta)
demand = -atan2(x_target, L)  # 转成度
```

这里 near 是赛道中心在图像右侧为正，即机器人相对赛道偏左。segments 模式优先使用已观测分段路径的目标点，要求近端锚定、宽度、残差和连续性检查连续3帧通过；不足时回退 heading。它仍继承后面的选档规则。没有显式补上此前讨论的机器人在画面底部后方15cm的坐标偏移。

active 滤波模式先滤波位置、方向和 demand。robust 默认使用最近3个有效样本的中值、时间常数0.45秒低通、45°/s变化率限制；无效帧不当作角度0。

选档的主要量是滤波后的 demand，不是 fused_err：

```text
corridor_angle = atan2(corridor_cm, target_depth)  # 度
left_gate  = min(right_tolerance_deg, corridor_angle)
right_gate = min(left_tolerance_deg, corridor_angle)
target_wz = side_cap * min(1, max(0, abs(demand) - side_gate) / full_scale_deg)
```

进入容忍区直行；超出后选择该方向最接近 target_wz 的可用非零档位，active 模式还在档位边界加迟滞。full_scale_deg 是超出容忍角后到转向上限的角度范围：越小越早选大档。它不是角速度单位换算，更不能证明模型指令等于真实角速度。

WZ_STEP 在 heading/segments 是幅值上限，会删除比上限大的档位。例如左档配置0.3、0.4、0.5，但 WZ_STEP=0.3 时只剩0.3。同时还受 MAX_WZ 和右转上限限制。若要保留这三档，需 WZ_STEP=0.5、MAX_WZ>=0.5。

当前按钮启动示例参数为 L=50、走廊5、右容忍9°、左容忍4°、full_scale=15。走廊角约5.71°，左转实际门槛被限制到约5.71°；把右容忍从9°进一步加大，不会放宽这个门槛。在上限0.5、左档0.3/0.4/0.5、迟滞1°时，同方向持续左转升到0.4的边界约17.21°，升到0.5约20.21°。这些是滤波后的 demand 阈值，且可能被下面的保护覆盖。

最终还经过以下规则：

- 位置已经偏离但方向正朝赛道内、前方目标落在走廊内时，允许直行收敛。
- 接近边界或目标越过走廊时，至少给相应方向的最低转向档。
- 原始 near>=+4cm 连续2帧，即确认机器人偏左时，禁止追加左转，改成直行。这条在 segments 模式也生效。
- 观测趋势向恢复方向发展时，用前方0.5秒的视觉趋势预测减弱当前转向，可能降到直行；不使用 wz×0.5 假装预测真实旋转。
- 当前分支视觉正常最短保持默认为0，逐帧选档。自动启动的模型入口 COMMAND_MIN_HOLD_S 也默认0，可另行配置；不能再说当前写死半秒保持。
- 本次默认 history-turn：没有可信几何时，短时沿用近期转向，最多0.8秒；无近期转向或沿用到期后，保持 vx、左转0.3。history-stop 兼容名称也采用新行为。外部停车继续优先。

因此转向变为0不一定是角度落进容忍区：也可能是偏左保护、趋势减弱、外部停车。定位时联看 steering_decision、steering_braked、steering_left_offset_confirmed、steering_reason、滤波 demand 和实际可用档位。
