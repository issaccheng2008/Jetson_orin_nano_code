# 分段观测接入实际转向

本次基于 `policy49` 的 `5be871f` 接入 `--wz-mode segments`。先前的 `--lane-fit-segments` 只记录诊断；新模式会自动启用这项观测，并将通过检查的中/远段目标点送进原 heading 控制状态机，实际发布 `vx/wz`。默认仍为 `heading`，方便沿用既有行为和做对照。

## 上机命令

手动启动原 A、C 后，沿用本次问题的 B 入口：

```bash
python -u new_vision/jetson/run_policy_vision.py --camera 0 --headless \
  --wz-mode segments --vx 0.2 --card-trigger-dist-cm 30 \
  --line-log-dir records/line_telemetry
```

比赛双闸、B 自动启动 C 的版本，只需把[当前上机命令](../../new_vision/机器人上机命令与参数_当前版.md)中 B 的 `--wz-mode heading` 替换为 `--wz-mode segments`，保留原先其他参数。

## 取哪些赛道信息

使用摄像机地面映射后的 20–32、32–44、44–56 cm 三个区间；每段只使用确实同时看见左右边界的行。近段负责与原有近端位置核对，中/远段给出前方中线目标。每段公开实际拟合内点的 `z_min_cm/z_max_cm`，目标限制在该观测范围内且不超过 `--heading-lookahead-cm`（默认 50 cm）。远段不足时可取中段最远的可信位置。

连续 3 帧稳定、近端锚定、至少 5 个点及 4 cm 深度跨度、法向宽度 26–44 cm、残差不超过 2.5 cm，才接受分段目标；相邻段间深度缺口不超过 4 cm，方向差不超过 35°，接缝横向差不超过 6 cm。当前宽度针对 35 cm 赛道。目标横向跳动超过 6 cm、方位变化超过 10°或切换目标段，需要重新确认。

目标方位为 `-atan2(目标横向位置, 目标深度)`。角度与横向走廊按同一实际目标深度计算。可信目标代替原来的近端切线外推；分段不足时使用原 `heading` 几何。实际应用仍由同一状态机持有正常命令至少 0.5 秒，保留原档位、限幅、近端保护、单边和丢线处理、图卡/起跑门控/静止覆盖。切换来源会清除不再可比的趋势历史，但不会提前结束命令保持。

## 如何判断排查是否对应实际问题

`line_frames.jsonl` 顶层的 `vx/wz` 是 B 实际发送的命令。`measurement` 中记录：

| 字段 | 含义 |
|---|---|
| `segment_control_active` | 当前帧几何是否接受分段目标；实际命令仍受保持时间与近端保护约束 |
| `segment_gate_reason` / `segment_confirm_frames` | 接受、确认中或回退的原因与连续帧数 |
| `segment_target_index/z_cm/x_cm/bearing_deg` | 当前候选目标所在段、位置和方位 |
| `segment_applied_wz` | B 实际应用的角速度命令 |
| `segment_shadow_vx/wz/reason/demand_deg` | 同一视觉输入上，独立原 heading 控制器的对照输出；只写日志，无发送通道 |
| `steering_reason` / `command_hold_remaining_s` | 命令保持、停车与最终控制决策 |

控制来源变化后，回退也要遵守已经开始的半秒正常保持，因此本帧 `active=false` 不表示已经立即改变发送的 `wz`。显式停车可立即打断，并把实际和对照输出都记为零。

实车验收需把 B、A、C 日志和视频对齐：检查进弯时可信远段是否提前给出正确方向、出弯时目标是否回到走廊内，以及实际轨迹是否改善。对照计算来自同一条实际行驶轨迹，只证明两种控制器会怎样选择命令；独立跑一趟 `heading` 才能比较两种模式的真实轨迹。不要将策略的 `vx/wz` 当成实测速度或转过的角度。
