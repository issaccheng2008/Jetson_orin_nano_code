# 非理想赛道边界追踪与模糊图卡预警：实现与证据

## 数据流

`LineDetector` 在旧连通域过滤之前复制黑帽阈值结果。`track_geometry.py` 将像素按连通线段的主轴采样，分别追踪左右边界；允许短暂断口和随距离变化的宽度，不要求直道平行或圆弧同心。双边可见时沿局部法线生成中心路径；单边只在最近有可靠双边宽度时产生低置信度路径。没有近处与前方实测支持就拒绝目标，不把 `wz` 当成实测角速度。

默认 `heading` 输出不变。加 `--track-observe` 才运行新观测，并在逐帧日志中写 `track_*` 和 `track_shadow_wz`。显式 `--wz-mode track` 才将连续 3 帧稳定的新目标送入原有 0.5 秒离散档位控制；不合格时退回 `heading`。弯道阶段需跨帧确认，避免单帧抖动解除左弯基础档。停车与起跑门控仍有优先权。

## 当前离线证据

- 用仓库已有的 216 张真机丢线邻近原图回放：旧 `heading_control_valid` 为 180 帧；新路径有 131 帧有效，其中双边 102、单边 29。新链是保守观测，**不能用有效帧数证明更会巡线**。部分画面中两链方向相差超过 15°，须逐张核对真实边界。
- 在本机 OpenCV 5 环境中，24 张原图的处理耗时中位数旧约 26 ms、开新观测约 30 ms；Jetson 实际耗时尚未测量。
- 四段 2026-09-19 实拍运动视频（每 2 视频帧取 1 帧，约 10 Hz）中，cue 门槛从 `2.0 / 9次取3次` 放宽到 `1.2 / 9次取2次`，第四段首次存在确认约从视频第 58 帧提前到第 46 帧；其他三段也提前。视频经缩放且不是当前板子数据，不能推出当前误停率。此前地板/反光样本 cue 上限约 0.78；新值仍保留结构筛选、跨帧确认和“确认后才给停车位置”。

## 复查命令与上线条件

```bash
python new_vision/scripts/replay_track_geometry.py records/loss_dump --output /tmp/track_replay.csv
```

当前比赛命令仍用 `--wz-mode heading`。先加 `--track-observe --line-log-dir records/line_telemetry` 收集同趟对照；针对方向分歧逐张看原图，特别是线缆、反光断线、左右边界出画和出弯。完成图像核对后再短程试 `--wz-mode track --wz-step 0.5 --heading-left-wz 0.37 0.43 0.5`，记录是否出界、踩线、误停和实际可用档位。没有这一步，不应把新模式改成默认。

图卡同趟保留 `[shape] cue=`、`found=`、`cy=` 和停车时刻；优先核查背景是否连续两次达到 `cue >= 1.2`，以及远处候选是否使 `card_armed` 正常重新建立。模糊 cue 仅用于存在／停车预警，六类投票未改变。
