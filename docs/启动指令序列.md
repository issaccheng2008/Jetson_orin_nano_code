# 按钮启动后的指令序列

此设置用于“起点首卡已识别并锁存 → 按按钮 → 启动步态 → 先移动 → 执行首卡”的先移动阶段。尚未识别首卡时按按钮，仍直接进入原有巡线流程；普通途中图卡的停车投票不受影响。

## 只调整直行时间

在 `config/button_start.env` 添加或修改：

```bash
STARTUP_FIRST_WALK_S=0.5
STARTUP_SEQUENCE=''
```

原来写死 1.0 秒，现在默认 0.5 秒。可以改为 0.3、0.8、1.0 等正数。直行速度使用原来的 `VX`，WZ 为零。

## 组合：直行半秒，左转半秒

```bash
STARTUP_SEQUENCE='[{"duration_s":0.5,"vx":0.2,"wz":0},{"duration_s":0.5,"vx":0.2,"wz":0.5}]'
```

依次执行：

1. 前进速度 0.2 m/s、WZ=0，持续约 0.5 秒。
2. 前进速度 0.2 m/s、左转角速度指令 +0.5 rad/s，持续约 0.5 秒。
3. 停车，执行已经锁存的首卡动作。

JSON 外面保留单引号、键名保留双引号。一段一个对象，用逗号连接，按书写顺序执行。非空 `STARTUP_SEQUENCE` 覆盖单段直行配置；该序列中的 VX/WZ 是每段自己的值，不读取全局 VX 来替换。

| 字段 | 意义与范围 |
|---|---|
| `duration_s` | 本段秒数，必须是大于零的有限数 |
| `vx` | 前进速度指令，单位 m/s，范围 0～1 |
| `wz` | 转向角速度指令，单位 rad/s，正数左转、负数右转、0 不转；绝对值不能超过 MAX_WZ（项目上限 0.5） |

可以再添加一段 `{"duration_s":0.2,"vx":0,"wz":0}` 表示停顿 0.2 秒。要右转，将相应 WZ 改为负数。空字符串恢复单段直行；`[]` 属于无效配置，不等价于关闭。参数错误在打开硬件之前报错。

## 生效与核对

```bash
cd ~/jetson_orin_code
git pull --ff-only
bash scripts/run_button_vision.sh --dry-run
sudo systemctl restart humanoid-button-vision.service
sudo journalctl -u humanoid-button-vision.service -f -o cat
```

启动日志显示实际序列。视觉 JSONL 中保留每帧已发送的 VX/WZ，并记录 `measurement.startup_sequence_index`（从 0 开始）和剩余时间；录像箭头也使用同一发送值。手动运行可传 `--startup-sequence 'JSON内容'`。

各段在视觉循环中切换，慢帧会延后切换；下一段从真正选中它的帧重新计时，不会因一次长延迟跳过整段。这是按视觉时钟调度的指令持续时间，实际运动距离和机身转角需要看反馈。

这些请求仍经过 connector 和步态程序：WZ_BIAS、限幅以及 COMMAND_MIN_HOLD_S 继续生效。组合时，最短保持时间不应大于最短段；否则某些非零指令可能延后甚至没有进入模型。最后的停车/动作接管仍会打断保持。核对模型实际使用的指令，查看 control CSV 的 cmd_vx/cmd_wz，而不是只看视觉日志。
