# 上位机逐阶段裁剪日志

日期：2026-10-04。覆盖 `humanoid_jetson_deploy/main.py` 与 `phase_clock_main.py`。

## 1. 这次补齐了什么

每次正常控制循环将模型输出、三层裁剪、实际发送参数、收到的下位机反馈、实际使用的参考状态放在**同一行**。walking、图卡单腿、独立单腿、固定关节帧、直立保持、phase-clock 共用此记录方式。

目标裁剪只计算一次：`TargetSafety.apply_with_trace()` 返回实际控制目标及该次计算的快照，实际发送直接使用返回的目标。没有另跑一套离线裁剪公式。裁剪顺序、三参数默认值、模型输入输出、关节映射、PD参数保持现有值。旧关节 CSV 和 phase-clock CSV 的表头/读取方式保留。

**当前验证是本机纯函数和替身串口测试，没有实车。** 日志提供下一次实车定值所缺的证据；目前不能据此宣称硬件的角度跟踪或实时性得到改善。

## 2. 启动与位置

新日志默认开启，无需修改现有启动命令。

| 入口 | 默认新日志目录 |
|---|---|
| `main.py` | `--position-log-dir` 所指定目录下的 `control_diagnostics/`；未指定时为 `records/motor_positions/control_diagnostics/` |
| `phase_clock_main.py` | `--log` 所指定文件的父目录下的 `control_diagnostics/`；默认 `logs/control_diagnostics/`（原有 `--log` 默认 `logs/phase_clock_run.csv`） |

每趟产生两个文件，启动打印完整路径：

```text
control_trace_<UTC时间>_<UUID>.csv
control_trace_<UTC时间>_<UUID>.manifest.json
```

用独立时间与 UUID、独占创建模式生成新文件，避免新运行覆盖旧记录。manifest 中的 `run_id` 与 CSV 每行 `run_id` 相同，`associated_legacy_log` 记录旧 CSV 路径。**旧 phase-clock 的 `--log` 文件仍按既有方式写入；需要保留旧日志时应给每趟不同的 `--log` 名。**

两个入口都支持：

```text
--diagnostic-log-dir <目录>    指定详细 CSV 和 manifest 的目录
--no-control-diagnostics      明确关闭此独立日志，启动打印已关闭
```

从仓库根目录启动示例（保留团队原有实车命令中的其他参数）：

```bash
python3 humanoid_jetson_deploy/main.py \
  --model humanoid_jetson_deploy/policy_49_v22.onnx \
  --port /dev/ttyACM0 --no-plot \
  --diagnostic-log-dir records/control_diagnostics

python3 humanoid_jetson_deploy/phase_clock_main.py \
  --port /dev/ttyACM0 --start-bind 127.0.0.1 --start-port 5008 \
  --log records/phase_clock_run_trial01.csv \
  --diagnostic-log-dir records/control_diagnostics
```

以上命令未带 `--enable-motors`，用于记录检查。实际行走使用团队已确认的运行命令，加上同一个 `--diagnostic-log-dir` 即可。三个可调裁剪参数仍按[上位机裁剪配置说明](上位机裁剪配置说明.md)使用；本次没有再修改其默认值。

## 3. 一行如何读

CSV schema 为 `control_target_trace_v2`，统一 301 列。关节组都带 12 个 `config.JOINT_NAMES` 后缀；目标单位 rad，速度 rad/s，`dt_s` 单位 s。

| 字段组 | 含义 |
|---|---|
| `requested_cmd_vx/vy/wz` | 源请求，尚未经过本地停车/接管和0.5秒保持覆盖 |
| `cmd_vx/vy/wz` | 本周期实际交给 walking 模型的速度命令，区别于请求 |
| `command_hold_remaining_s` | 固定0.5秒合同的剩余时间；主机单调时钟 |
| `command_hold_reason` | normal_walking / stop / upright_takeover / onefoot_takeover / not_walking |
| `raw_action_*` | 本次 ONNX 输出的原始动作；固定帧、保持姿势和序列结束填空 |
| `raw_target_policy_*` | 策略返回、尚未经过目标裁剪的关节目标 |
| `absolute_target_policy_*` | 应用绝对上下界及 margin 后的目标 |
| `slew_target_policy_*` | 应用与上次最终目标之间的速度限制后的目标 |
| `final_target_policy_*` | 再应用反馈窗口后的最终目标 |
| `motor_send_argument_*` | 经过 `policy_to_motor_position()` 后，实际传给 `SerialLink.send_command()` 的 12 个数 |
| `previous_final_policy_*` | 本周期 slew 使用的上一最终目标；首行由初始反馈转换而来 |
| `reference_q_policy_*` | **本周期反馈窗口真正使用的 q**；恢复保持期间可能来自旧快照 |
| `reference_qd_policy_*` | 本周期实际交给策略的 qd，保持期间同样可能来自旧快照 |
| `received_q_packet_*`, `received_qd_packet_*` | 本周期从 STM32 包读到的位置、速度，保留包坐标 |
| `received_q_policy_*`, `received_qd_policy_*` | 将同一个收到的包转换到 Nano 策略坐标后的值 |
| `absolute_clip_mask_*` | 本级输出与原始目标是否不同，0/1 |
| `slew_clip_mask_*` | 本级输出与绝对裁剪结果是否不同，0/1 |
| `window_clip_mask_*` | 最终结果与 slew 结果是否不同，0/1 |

**收到的包不是物理编码器原始真值。** STM32 可能已经裁剪、冻结或处理这些反馈。本协议没有传回 STM32 内部反馈冻结开关，因此不能从 `held_reference=0` 推断下位机反馈一定未冻结。`held_reference` 仅表示 Nano 本周期是否采用自己的恢复保持快照。

`window_clip_mask` 统计最后一级的变化。反馈窗口启用时，最后一级使用反馈窗口与绝对边界的交集；反馈窗口禁用时，仍会重查绝对边界。因此这个 mask 不能一律解释为“10°窗口触发”。分析时必须读取 manifest 中的实际参数。

三层数学顺序保持为：

```text
A = clip(raw_target, lower + margin, upper - margin)
S = previous + clip(A - previous, -speed*dt, +speed*dt)   # speed=0 时 S=A
F = clip(S, max(lower+margin, reference_q-D), min(upper-margin, reference_q+D))
# D=0 时关闭相对窗口，F 仍按绝对边界裁剪
motor_send_argument = policy_to_motor_position(F)
```

单腿左支撑还有已有的镜像映射：模型原始动作保持标准模型坐标；`raw_target_policy` 已按 `-concat(action[6:], action[:6])` 换算到实际腿的策略坐标后再加默认角度。不要在左支撑时直接用未镜像的 `raw_action` 与对应物理腿目标相减。日志记录 `support_foot`，manifest 说明此映射。

### 周期、状态与命令

- `row_index` 是该文件连续行号。`step` / `phase_tick` 是调用方的控制步或 phase-clock 名义 tick；后者可能重复或跳号。
- `dt_s` 是**裁剪实际使用的 dt**：主循环使用现有 dt，phase-clock 保持原有固定 0.02 s。不要将它误读成由日志推导的两行发送间隔。
- `state_sequence`、`state_timestamp_us`、`state_flags` 记录收到包的身份。`state_receive_monotonic_s` 与 `state_receive_age_s` 查找这个具体包的主机接收时间，即使读取后已有新包抵达也不会换成新包时间。
- `state_receive_metadata_available=0` 时接收时间与年龄填空，不假装是 0 ms。旧传输替身、接收索引已淘汰等情况下可出现该标记；索引仅保留最近 64 个包身份。
- `read_monotonic_s`、`command_timestamp_us`、`send_done_monotonic_s` 可用于对齐读反馈与发送动作；`host_unix_s` 可与其他设备的墙钟记录近似关联。STM32 时间戳与主机时间戳来自不同时间基准，不能直接相减。
- `command_flags`、`card_tilt_active`、`upright_hold`、`held_reference` 记录本周期开关状态；IMU同时保存收到包与实际参考值，四元数保留收到包的 WXYZ 顺序。
- `cmd_vx/cmd_vy/cmd_wz` 保存所用速度命令，单腿另有 `lift_command/support_foot`；walking 与 phase-clock 记录 `command_step_distance_m/command_crossing`。单腿夹带的视觉速度如果存在，表示同时存在的视觉命令，不属于其46维模型输入。
- `policy_mode` 分清 walking49、onefoot46、fixed、upright_hold、phase_clock。`phase` 记录图卡控制阶段、独立单腿 standing/lift、固定帧或 phase-clock 阶段；固定帧另有零基 `phase_tick`。

### 实际输入与非模型目标

`observation_0..48` 保存本次实际模型输入。`obs_dim=49/46` 与 `observation_available=1` 表示模型调用；46维行的最后3列填空。walking/onefoot 使用策略返回的本次观测；phase-clock 使用同一构造函数及**更新动作历史前**的 last_action 还原，集成测试逐值对照实际推理收到的输入。

`target_source` 分别为：

| 值 | 说明 |
|---|---|
| `onnx` | 模型目标，有原始动作和输入 |
| `fixed_joint_frames` | 固定帧 JSON，原始动作和输入填空 |
| `hold_upright_zero_target` | 直立保持的原有零角度目标，原始动作和输入填空 |
| `initial_pose_hold` | phase-clock 等启动时保持上次目标，原始动作和输入填空 |
| `sequence_end_no_target` | phase-clock 结束帧，无新目标和发送；各级目标、动作填空，`send_result=not_attempted` |

`send_result=written` 只表示 `send_command()` 返回 True；`not_written` 表示返回 False，`error` 表示发送抛异常，`unknown` 表示其他接口没有返回明确布尔结果。**它不是 STM32 已接纳、CAN 已执行或电机已到达的回执。** 循环退出后的既有失能/急停包不冒充一个新模型周期，未写入本周期 CSV。

## 4. 每趟 manifest 必须保留

manifest 包含本次命令参数与进程 argv、源模型 SHA256（walking、单腿、图卡单腿或 phase 模型）、phase 合同/时钟文件身份、绝对上下界和来源、可选限位 JSON 的 SHA、三参数实际值、关节顺序、motor sign/zero、IMU变换、默认角度、动作缩放、观测模式、完整301列表头、初始反馈及关联旧 CSV 路径。

SHA在开始记录时读取文件，缺文件会打印原因并在 manifest 中明确标为 `source_file_missing`，不会写伪 SHA。实车加载真实模型成功时应有模型 SHA。固件版本目前协议没有回传，固定标为 `unknown_not_reported_by_protocol`；不能据此确定实车正在运行哪版 STM32。

正常关闭更新 `status/rows_written/error`。进程被强杀或断电时 manifest 可能仍是 `running`、`rows_written=0`，应按实际 CSV 解析出的行数判断，不把该字段当作已同步的实时计数。

## 5. 写入与失败的处理

CSV使用64 KiB缓冲，每50行 flush 一次，正常退出再 flush；没有逐周期 fsync。硬中断可能丢失最近一批尚未 flush 的记录。新日志的格式化及磁盘写入仍占用控制线程，**未在 Nano 上测过耗时**；用发送时间间隔和原有 deadline warning 检查本趟节拍。可显式关闭新日志作同参数对照。

数组维度、非有限数、未知字段和记录目标与实发参数不一致都抛出明确错误；发送错误尽量写入当行；写入失败向外传播，走既有 fault/失能路径。不会静默丢日志后继续声称记录完整。磁盘满也可能阻止 fault manifest 写入，终端错误必须一起保留。

## 6. 如何回答“10°与 slew 实际限制多少”

对每一关节，分别统计三个 mask 的触发比例和相邻阶段差的角度分布：

```text
绝对级改动 = absolute_target_policy - raw_target_policy
slew级改动 = slew_target_policy - absolute_target_policy
窗口级改动 = final_target_policy - slew_target_policy
总改动     = final_target_policy - raw_target_policy
实际参考差 = final_target_policy - reference_q_policy
收到反馈差 = final_target_policy - received_q_policy
```

同一行可出现两个或三个 mask，所以不要将触发票数当作互斥类别相加。先按 model SHA、policy_mode、support_foot、phase、held_reference 和三参数分组，再比较不同运行。phase-clock 的结果不能直接代替 walking 的结论。

## 7. 本机验证

新增 `tests/test_control_diagnostics.py` 的8项测试覆盖：逐阶段快照与原控制结果一致；各级 mask；冻结参考与收到反馈分列；独立文件不覆盖、manifest SHA及schema；46/49/无模型输入；错误配置/写入故障显式失败；具体包接收年龄；两个真实入口所送目标与日志逐值一致；phase 记录的输入与实际推理输入逐值一致；fixed/onefoot/upright 正确标识来源。

连同原有裁剪、walking、图卡分流、phase-clock、fixed、onefoot、观测日志和协议相关测试，共 **70项通过**，耗时约4.3秒。详见 [control_diagnostics_verification.txt](control_diagnostics_verification.txt)。这些是本机替身和纯函数验证，未连接串口电机，未使用它们证明实车跟踪性能。
