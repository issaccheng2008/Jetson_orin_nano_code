# 上位机关节目标裁剪运行参数

2026-10-04。本机实现，未提交，未连接实车。普通入口`humanoid_jetson_deploy/main.py`与跨棍入口`humanoid_jetson_deploy/phase_clock_main.py`共用`target_safety.py`的运行期配置。`main.py`内walking、one-foot、固定JSON帧及直立保持分支使用同一处理链。

## 1. 参数

| 参数 | 默认 | 设0时 | 单位与对象 |
|---|---:|---|---|
| `--max-target-speed-rad-s` | 3 | 关闭关节目标slew限制 | rad/s；限制相邻目标变化，非电机实际速度 |
| `--max-target-deviation-deg` | 10 | 关闭围绕反馈的目标窗口 | 度；非每一步总幅度 |
| `--joint-limit-margin-rad` | 0.05 | 只移除绝对上下界内的margin | rad；绝对上下界仍生效 |
| `--joint-limits-json` | 不指定 | 不适用 | 可选绝对12关节上下界文件，policy坐标、弧度 |

均要求有限非负值；负数、NaN、Inf在打开电机串口之前拒绝。自定义上下界必须为12个有限角度、lower<upper，margin不能把任何关节的可用区间吃空。即使slew和反馈窗口都关闭，target/current/previous仍检查12维与有限性，NaN不会被放行。

默认值保留此前行为，顺序保持**绝对上下界及margin → 目标slew → 相对反馈窗口**。当前处理顺序中，最后的反馈窗口可能覆盖前级slew结果；这次只实现可调参数，没有改约束顺序或解决其交集冲突。

每次启动打印全部生效值及12关节绝对上下界：

```text
Target limits: margin=0.05 rad; slew=3 rad/s (0=off); feedback-window=10 deg (0=off); absolute-lower=[...]; absolute-upper=[...]
```

该配置是每次运行的独立对象，不修改`config.py`全局变量。既有`config.clamp_policy_target()`、`config.clamp_policy_target_to_current()`保持原API；既有`main.slew_limit()`保持默认3rad/s行为。GUI电机调试工具尚不读取这些新的CLI参数。

## 2. 普通模型入口示例

保留默认裁剪，固定命令走5秒：

```bash
python humanoid_jetson_deploy/main.py \
  --model humanoid_jetson_deploy/policy_49_v22.onnx \
  --command-source fixed --vx 0.2 --wz 0 --walk-seconds 5 \
  --step-cm 5 --enable-motors --no-plot \
  --max-target-speed-rad-s 3 \
  --max-target-deviation-deg 10 \
  --joint-limit-margin-rad 0.05
```

针对目标slew对动作波形的影响，其他参数固定，仅把`--max-target-speed-rad-s 0`。针对反馈误差窗口，其他参数固定，仅把`--max-target-deviation-deg 0`。关闭这两个限制不是修复模型与硬件差异的充分条件，比较应记录raw target、最终target和actual，尤其要先确认关节身份映射。

与视觉、单腿或固定帧组合时，将同一组三参数加到已有`main.py`命令。例如单腿的`--policy one-foot --model humanoid_jetson_deploy/policy-one-foot-standing.onnx`、固定帧的`--fixed-policy humanoid_jetson_deploy/examples/fixed_joint_frames.json`均会使用这组配置。固定帧在加载时按本次绝对界与margin验证，而不是按另一套默认范围验证；slew和反馈窗口仍作用于每帧实发值。

## 3. 跨棍入口示例

```bash
python humanoid_jetson_deploy/phase_clock_main.py \
  --port /dev/ttyACM0 --start-bind 127.0.0.1 --start-port 5008 \
  --enable-motors --log records/phase_clock_run.csv \
  --max-target-speed-rad-s 3 \
  --max-target-deviation-deg 10 \
  --joint-limit-margin-rad 0.05
```

另一个本机终端仍按已有启动方式发送：

```bash
python humanoid_jetson_deploy/tools/send_phase_start.py --port 5008
```

初始姿势检查与`--pose-tolerance-deg`、`--max-joint-speed`仍独立存在；目标窗口参数不替代启动条件。phase-clock仍随墙钟推进，其slew使用名义20ms；本次未改动作相位计时。

## 4. 绝对界JSON

JSON必须只包含三个字段：`joint_names`、`lower_rad`、`upper_rad`。名称及顺序严格等于`config.JOINT_NAMES`，即模型侧右腿六关节在前、左腿六关节在后；这不是对STM32物理左右顺序冲突的修复。

可从现有默认值生成文件：

```bash
PYTHONPATH=humanoid_jetson_deploy python - <<'PY'
import json
from pathlib import Path
import config
Path('joint_limits.json').write_text(json.dumps({
    'joint_names': list(config.JOINT_NAMES),
    'lower_rad': config.Q_LOWER.tolist(),
    'upper_rad': config.Q_UPPER.tolist(),
}, indent=2) + '\n', encoding='utf-8')
PY
```

按已标定的物理范围调整其中12个数，然后在上述任一入口命令中加`--joint-limits-json joint_limits.json`。上下界均为绝对角弧度，margin在读取后另行应用。未知字段、错序名字、11或13个数、非数值、NaN/Inf、倒置上下界都会拒绝。

未指定文件时，绝对界来自`config.Q_LOWER`与`config.Q_UPPER`；可统一在该模块修改默认界。本次优先支持CLI/JSON，避免每次调参修改代码或一个进程改了另一个进程的全局配置。

## 5. 验证

新增`test_target_safety_config.py`的7项测试覆盖：40组随机目标的默认公式逐值一致；自定义speed/window/margin生效；0关闭对应级且绝对界仍在；关闭后仍拒NaN/错误维度；JSON与固定帧范围一致；两入口CLI拒非法值；walking、one-foot、fixed及phase实际控制入口将配置应用于送出的目标。

另外通过既有policy/fixed、shape、walking、phase-clock、target-window与观测日志测试。测试为本机纯函数、临时文件和通信/策略替身，不代表实车动作或接触验证。
