# 非对称档位与防过纠偏

2026-10-04，继方向融合方案之后的本地修改。以本文为当前heading模式说明；旧回放与旧参数表保留用于追溯。本次提交包含本地实现及验证材料；未连接或部署到实车。

## 1. 已按用户要求固定档位

| 动作 | 可选强度 | 默认yaw_sign=+1时发送wz |
|---|---|---|
| 直行 | 0 | 0 |
| 左纠偏 | 0.4、0.5 | +0.4、+0.5 |
| 右纠偏 | 0.1、0.4、0.5 | −0.1、−0.4、−0.5 |

heading模式现在默认两侧都能纠偏，不用再加 `--wz-allow-right`。该开关仅保留给旧discrete模式。以上是几何左右；`yaw_sign=-1`仅反转模型命令符号，不交换物理方向的档位。

正常 `(vx,wz)` 每组仍至少保持0.5秒，直行也一样。全零停车、失联和接管继续立即抢占。本次不改A转发、C模型保持、关节裁剪或STM32。

## 2. 分开角度容忍和横向限制

仍从可信地面方向和near位置算目标方位：

```text
e = near处赛道中心横坐标（画面右为正）
θ = 地面赛道方向（向前朝左为正，即机身相对赛道朝右）
x_target = e - (L - near_z) * tan(θ)
α = -atan2(x_target, L)
```

新增 `--heading-corridor-cm 8`：近处测量及前方目标的横向限制，和角度容忍独立。8cm是暂定调参初值，不是已测机器人足部安全余量，也不是保证不出赛道的物理边界。

- 若前视目标横偏达到8cm，或近处横偏达到8cm且仍平行/朝外，就进入相应纠偏。
- 走廊纠偏至少使用0.4；右转0.1只用于走廊内的小调整。
- 放宽 `--heading-right-tolerance-deg` 不会放宽8cm横向限制。
- 默认L=50cm，8cm对应目标方位约9.09°，因此正方向实际触发不晚于9.09°，即使右容忍仍填12°或更大。负方向仍可在4°先用右转0.1。

这里检测的是near位置和局部直线外推的前视位置，不能当作测到了脚底相对赛道边界的距离。地面拟合、相机晃动或选错线仍会影响判断。

## 3. 何时收回直行，避免左转过多

**不等横向误差归零。** 若位置偏右、方向已朝左，且前视目标已经回到±8cm内，半秒保持结束后收回直行；镜像情况同理。让已有朝向逐渐消除残余位置偏差。

仅仅方向略朝内还不够：例如near=-12cm、方向=-0.1°，前视目标仍偏在外侧，继续左纠偏0.4。near=-12cm、方向=-15°时，前视目标已进范围，可直行。

保留已有视觉趋势预测：同一命令下最近半秒估计目标方位变化趋势，在需求减小时减少下一段纠偏。新幅度的真实响应未知，仍不使用 `wz×0.5` 推算真实转角。

走廊决策与趋势刹车的优先级已修正：预测仍在外侧时，不允许降成0.1；预测已回到范围内时可以收回0。单独预测“方向过零”不再足以停止纠偏，还要结合位置形成的目标方位。所有正常收手都等当前0.5秒合同完成。

## 4. 档位选择与参数

首先计算连续需求，再选最接近的允许非零档，等距时选较小档。左转不输出0.1/0.2/0.3，右转不输出0.2/0.3；不是先量化再被限幅削成其他值。

连续需求为：`方向可用上限 × clip((超出有效触发角的度数)/full_scale_deg,0,1)`。边界保护覆盖弱档，回拢和预测规则可以将输出降为0。

| 参数 | 当前默认 | 调节含义 |
|---|---:|---|
| `--heading-corridor-cm` | 8 | 横向容忍上限，越小越早介入；不要通过放宽它掩盖过转 |
| `--heading-right-tolerance-deg` | 12 | 对正目标方位的容忍，受走廊上限约束 |
| `--heading-left-tolerance-deg` | 4 | 负目标方位的小纠偏起点，右转0.1可在这里生效 |
| `--heading-lookahead-cm` | 50 | 前视深度；必须大于near测量深度 |
| `--heading-full-scale-deg` | 20 | 档位强度需求的增长速度；越小越早选0.5 |
| `--wz-step` | 0.5 | 本模式档位上限；改成0.4只移除0.5档，不生成0.45档 |
| `--max-wz-right` | 0.5 | 最终负wz上限；低于0.4在heading模式拒绝，避免边界缺少纠偏档 |

使用默认上限0.5时：左方向超出有效触发角约18°后才选0.5，此前为0.4；右方向走廊内可选0.1，触及走廊至少0.4，强需求再到0.5。档位已指定，是否具备这些真实转向力度尚未实车确认。

## 6. 使用与验证边界

B原命令保留相机、图卡和记录参数，控制项使用：

```bash
python -u new_vision/jetson/run_policy_vision.py --camera 0 --headless \
  --wz-mode heading --vx 0.2 --wz-step 0.5 --max-wz 0.5 \
  --heading-lookahead-cm 50 --heading-corridor-cm 8 \
  --heading-right-tolerance-deg 12 --heading-left-tolerance-deg 4 \
  --heading-full-scale-deg 20 --line-log-dir records/line_telemetry
```

新日志 `steering_decision` 标明 target_bearing、right_corridor、left_corridor、returning_from_right/left；只在到达决策时刻写出，保持期间 `steering_reason=minimum_hold`。输出档位、趋势、ground方向与保持剩余时间继续记录。

验证包括允许档位集合、半秒保持、左右反号与限幅、实际near深度、放宽角容忍仍保护横偏、已向内时停止过转、微小向内反例，以及走廊保护被趋势降为弱档的反例。571帧使用上次真实视频检测缓存重新运行控制器：没有重跑图像检测，更没有让新命令实际驱动车辆。

最新验证数字与源码身份见[档位回放目录](heading_levels/)。0.4最短半秒是否仍会过转，取决于机器实际响应；当前代码和录像无法保证不出界。如果这个最小动作本身就超过可用转角，需要重新核对允许档位或训练合同，不能靠继续放宽右容忍解决。


### 本次缓存回放结果

571帧中输出均落在指定六种值，25段完整正常命令没有短于0.5秒的切换；因几何失效产生的双零仍为48帧、9次安全中断。相较上一版控制器，转向帧从166增到378，主要包含本次启用的右纠偏，不能解释成跟踪改善。

还观察到7帧已经向外超出8cm，但因为原命令尚未满0.5秒，仍保持直行或0.1。**8cm限制在下一次允许决策时生效，不是每帧可抢占的硬防出界系统。** 这正是固定半秒与及时纠偏的取舍；图像抖动可能放大这些偏差，离线记录不能定真实位移。当前没有为了这一反例静默破坏半秒合同，也没有声称它能保证不出界。

最终Windows OpenCV视觉回归 **231项通过**，Linux新控制器 **22项通过**（已包含在231项中，不重复累加）。[完整测试输出](heading_levels/vision_regression_231.txt)与[当前源码身份](heading_levels/implementation_manifest.json)已保存。
