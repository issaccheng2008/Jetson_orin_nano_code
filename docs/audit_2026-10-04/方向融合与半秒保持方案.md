# 方向融合与半秒保持方案

> 后续用户已指定左右档位，当前实现见[非对称档位与防过纠偏](非对称档位与防过纠偏.md)。本文连续幅度、默认仅左纠偏及数值示例属于上一版；回放结果保留追溯。

2026-10-04，本机实现与离线验证，本次提交包含实现与离线验证；尚未部署或实车闭环验证。

## 1. 改动结论

新增 `--wz-mode heading`，并作为视觉入口默认模式。时间上分段保持，幅度上连续选择：不再只给0和0.5；正常行走每组 `(vx,wz)` 至少保持0.5秒。旧 `discrete` 与 `continuous` 视觉算法仍可显式选择，但配套新C之后，正常 walking 模型输入都遵循0.5秒合同。

**模型接收的是速度条件 `vx,wz`，不是目标航向角。** 本次扩大的是可选转向强度；没有扩大ONNX输入维数、增加绝对航向接口、重新训练模型，也没有证明小幅命令是有效步态。视觉链路幅度上限仍为0.5；新模式拒绝 `--wz-step > 0.5`，避免连接器默默裁剪。

位置与方向共同形成几何需求，不要求两项分别同时过门槛。保留向右偏的较大容忍，减小不必要的左纠偏。默认仍只允许左纠偏；两侧都需要纠偏时加 `--wz-allow-right`，两边容忍区仍不对称。

## 2. 数据流与固定0.5秒

```text
可信成对赛道点 → 地面厘米坐标拟合方向
 + near处位置/深度 → 前视目标方位 → 三帧中位数
 → 非对称容忍区/连续幅度 → 已有纠偏的趋势刹车
 → B成对保持≥0.5秒 → UDP command_mode=held
 → A跳过vx/wz斜率，持续50Hz转发
 → C模型调用前再次成对保持≥0.5秒 → ONNX → 原关节映射/裁剪/串口
```

- **B**：首次选定一组命令后计时；相同值的重复发送不续期。直行 `(vx,0)` 也必须保持，普通回中不能提前结束半秒。
- **A**：`held` 跳过两条斜率限制；无标签/`continuous` 仍走原平滑。全零、直立/低头标志、超时立即双零并清平滑状态。不是每半秒才发一次UDP，心跳频率保留。
- **C**：从该组数值第一次真正交给 walking 模型开始，用主机单调时钟计满0.5秒。期间仅保留最新请求，不排队执行过期请求；到期后下一次推理采用最新值。
- **抢占**：全零停车、看卡停车、丢线超时、UDP失联、直立/单腿接管、故障/退出可以立即中断。重新启动建立新合同。
- C作用于 walking 的视觉/固定/scripted/curve命令，不改固定关节序列、独立单腿或 phase-clock。原来短于0.5秒的普通脚本段可能被延后或跳过，不能再期待逐段原样播放。
- A、B、C需要配套更新。B与C时钟不共享段起点；最终模型命令可能比B发布晚一个或多个推理周期。C详细日志中的实际值才是模型输入依据；本次未新增STM32执行确认协议。

## 3. 如何同时使用方向和位置

取机器人前方为 `z>0`、图像右为 `x>0`。`near_error_cm=e` 是在 `near_z_cm=z_n` 处看到的赛道中心横坐标，实拍通常在20–30cm；不是脚下偏差。地面拟合方向 `θ>0` 表示赛道向前延伸时朝左，即机器人朝向相对赛道偏右。

从同一批可信成对点得到 `x=a*z+b`，方向为 `θ=-atan(a)`。旧图像角字段仍保留；新控制用 `heading_control_deg`，消除旧固定IPM横纵比例对角度的影响。相机标定/机身晃动/错误选线的影响仍然存在。

在前方 `L=50cm` 处取目标：

```text
x_target = e - (L - z_n) * tan(θ)
α = -atan2(x_target, L)
```

`α>0` 表示需要左纠偏。这样，偏离赛道但已经朝回来的情况会自动抵消一部分转向；方向很歪而near偏差很小，也能产生纠偏。避免把有投影关系的error与方向任意加权。

当前按最后三次可信 `α` 取中位数，再映射强度。`L` 必须大于实际near测量深度；不满足时判为几何不可用。这里是局部直线外推，**不是检测到了50cm处的真实弯道中心**。仅6–8cm深度跨度的点受晃动时，外推仍会放大方向误差；ground RMSE/跨度已记入日志，但尚未据此增加新的阈值。

## 4. 参数机制与非对称

| B参数 | 默认 | 对结果的影响 |
|---|---:|---|
| `--heading-lookahead-cm` | 50 | 目标平面深度。增大时，平行横偏贡献减小、near=0时方向贡献增大；不能简单视为固定“方向权重” |
| `--heading-right-tolerance-deg` | 12 | 正目标方位的容忍区；越大，左纠偏越晚、越少 |
| `--heading-left-tolerance-deg` | 4 | 负目标方位的容忍区；启用右纠偏后生效 |
| `--heading-full-scale-deg` | 20 | 越过容忍区后，再增加多少度才到幅度上限；越小输出越强 |
| `--wz-step` | 0.5 | 本模式幅度上限，不再是唯一非零档位；不能超过0.5或 `--max-wz` |
| `--wz-allow-right` | 不启用 | 启用后允许右纠偏；否则负需求只直走 |
| `--max-wz-right` | 同max-wz | 最终负wz的上限；`yaw_sign=-1`时仍按输出负号应用 |
| `--yaw-sign` | +1 | 仅映射几何转向与模型命令的正负，不改变视觉几何 |

默认 `yaw_sign=1` 时：正需求输出 `0.5 * clip((α-12)/20,0,1)`；启用右纠偏后负需求使用4°容忍区和对应上限。超过容忍区2/4/8/14/20°时，分别可得到0.05/0.1/0.2/0.35/0.5。旧PID、bias、fire/stop/turn/gap参数不参与新模式；可信度、几何有效性和丢线保护仍参与。

**12°/4°是目标方位的容忍，不是机身方向的直接容忍。** 初始值表达设计意图，尚未实车定值。例如首次可信观测、无历史时：

| near cm | near深度 cm | 地面方向 | 目标方位 | 默认wz |
|---:|---:|---:|---:|---:|
| 0 | 25 | +20° | +10.31° | 0 |
| 0 | 25 | +25° | +13.12° | +0.028 |
| 0 | 25 | +35° | +19.30° | +0.182 |
| −10 | 25 | 0° | +11.31° | 0 |
| −17.5 | 25 | 0° | +19.29° | +0.182 |

near=0且深度20/25/30cm时，开始左纠偏所需方向约19.5°/23.0°/28.0°。方向平行时12°容忍等效目标横偏10.63cm，这个容忍可能过宽；靠近边界时0.182也未必足够。若实车显示纠偏太晚，优先减小右容忍；若开始及时但力度不够，再减小full-scale，分开调以区分原因。不要把本表当作已确认的有效步态表。

## 5. 半秒趋势预测的范围

用同一命令下最近0.5秒的视觉观测估计变化率：至少3点、时间跨度至少0.3秒，取间隔至少0.2秒的点对斜率中位数。预测 `α_future=α+0.5*dα/dt`，方向趋势也记录到日志。

仅在**正在同向纠偏、观测需求正在减小**时，用预测收小下一段转向；不能超过当前幅度，不能靠预测反向。换命令或丢测量即清历史。没有用 `wz*0.5` 假装真实转角，也没有把视觉方向变化当可靠IMU yaw。

这不是完整的动力学预测控制：不会因为预测越过容忍区而提前启动第一次纠偏；也不能预测尚未执行的新幅度的响应。要把“每个航向都有效”变成证据，仍需未来实车中的实际模型命令、视觉方向变化和执行反馈对齐。现有录像没有新命令对应的物理响应。

## 6. 离线验证与已知代价

- Windows OpenCV环境：仓库 `tests/` **222项通过**，含新控制器14项、真实B入口/UDP3项、connector22项，以及既有视觉/图卡回归。
- 模型输入及相关回归：**79项通过**。真实观测构造确认0/.1/.49秒输入不变，到.5秒采用最新请求；全零/真实UDP超时可抢占。
- Robocup四段原始晃动录像，共571帧，按视频FPS推进时间；逐帧比较旧Discrete和新Heading，保存输入、配置、源码SHA和命令段。
- 14个可评估的正常完整命令段，短于0.5秒的切换为0；最短约0.549秒。视频尾截断、初始等待与安全停车单独统计，不算正常保持违规。
- 518帧位置测量有效，435帧同时有可信方向。**新方案双零48帧、旧方案3帧；新方案有9次几何丢失抢占。** 方向缺失而位置仍有时，新方案会更容易停止。这是当前版本的实际不足，没有用旧图像角强行补上无效新方向。
- 新方案166帧转向、旧方案94帧；11帧触发趋势刹车且未增大已有幅度。转向更多不等于跟踪更好，视频回放不能验证新轨迹或0.5秒真实执行效果。

证据：[回放目录](heading_hold/replay_final/)、[逐帧CSV](heading_hold/replay_final/per_frame.csv)、[命令段CSV](heading_hold/replay_final/command_segments.csv)、[222项输出](heading_hold/vision_regression_222.txt)、[79项输出](heading_hold/model_input_regression_79.txt)。回放冻结的控制器与检测器和当前生产一致；冻结之后入口仅增加拒绝幅度>0.5的校验，不影响本次0.5幅度配置。
