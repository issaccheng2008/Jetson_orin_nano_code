# 视觉 P1 实拍离线验证

日期：2026-10-04。本报告使用已有机器人相机画面，不连接实车，不发送动作。

## 验证口径

最终只比较两个冻结的源码快照：P1 修改前的 `vision_p1_baseline/`，以及完成扫描覆盖、失效事件和厘米 EMA 修复后的 `vision_p1_after_release/`。每个快照保留 detector、policy、discrete 三个文件和 SHA256。最终 detector SHA256 为 `37ef07d4c2707c29e6d1d938ba4fbf2f88fa4c9de3908c8943a07c338c407781`。

另保留中间源码 `vision_p1_after/`、`vision_p1_after_final/`，以及第一轮 790 帧结果 `vision_p1_replay/`。**最终结论使用 `vision_p1_replay_final/`**，没有覆盖中间证据。

输入是 `records/loss_dump*` 的 **219 张原始 frame 图片**，以及 Robocup 下 **4 个原始 `*_flip.mp4` 录像、571 帧**。不把 `*_line` / `*_shape` 注释副本再计为数据，也不把手机外部拍摄当成机器人巡线相机输入。

| 原始机器人录像 | 帧数 | 文件报告 FPS | 给控制器/支持 dt 的 detector 的 dt |
|---|---:|---:|---:|
| `WIN_20260919_18_10_34_Pro_flip.mp4` | 134 | 20.032 | 0.049920 s |
| `WIN_20260919_18_11_50_Pro_flip.mp4` | 139 | 20.014 | 0.049965 s |
| `WIN_20260919_18_13_14_Pro_flip.mp4` | 173 | 20.020 | 0.049950 s |
| `WIN_20260919_18_13_53_Pro_flip.mp4` | 125 | 20.028 | 0.049930 s |

每段视频使用连续的 detector 和控制器状态，保留默认 `startup_settle_frames=25`。控制器经过的时间来自 `1/FPS`，不是本机处理耗时；每帧都处理，没有抽帧来加速。P1 前的 detector 没有 dt 参数，仍运行原来按帧更新的路径。

单张 loss 图片每张新建 detector，明确设置 `startup_settle_frames=0`，控制器 dt=0.05 s。它只能检验单张画面的几何/质量/有效性，不能重建停车、重获、EMA 历史或者当时的实车控制输出。图像的保存 JSON 是旧运行状态，不能当成这个新控制器的真值。

两个版本使用相同相机参数：usb_main 的高度 32.5 cm、俯角 45°、VFOV 55.876°、距离校正 a=1.13233 / b=-2.4862、车道宽 35 cm；使用输入原生分辨率，不缩放巡线输入。控制器固定 vx=0.2、wz=0/+0.5、fire=5 cm、stop=5 cm、turn=1 s、gap=2.5 s、lost_hold=0.2 s、yaw_sign=+1，红条检测开启。这是固定诊断条件，**不是对历史实际运行命令的复原**。

脚本禁止覆盖已有 before/after CSV；可用 `--output-dir` 指定新目录、用 `--source-dir` 指定另一个已冻结源码快照，保留每次产物。比较前检查完整输入图片/视频 SHA256、相机配置、控制器参数都相同。

`vision_p1_replay_final/` 内：

- `before_frames.csv` / `after_frames.csv`：每帧 near、heading、fused、quality、lock、有效性、失效、wz、phase 时钟、处理耗时和 detector 的全部标量 debug。
- `paired_frames.csv`：同一输入逐帧配对及变化量。
- `before_summary.json` / `after_summary.json`：分 loss 目录、分视频汇总，输入/源码/配置 hash，Python / OpenCV 版本。
- `inspection_selected.json` / `inspection_*.jpg`：人工看图的明确候选和前后鸟瞰结果；候选依据是机制/变化量，未作为人工真值标签。
- `mechanism_checks.json`：坏锁权重、观测失效后控制接受、丢线指令过期的硬检查。
- `association_counterexample.json` / `association_counterexample_overlay.jpg`：疑似错误关联点经原 IPM 逆变换投回原图的位置。
- `mode_source_sample.csv` / `mode_source_sample_summary.json`：受限抽样的候选模式来源，避免用一个反例禁止整个 fallback。

## P1 前的参考结果

219 单张里 206 张通过旧控制有效性，底锁有效 45 张；571 视频帧里 545 帧通过旧控制有效性，底锁有效 55 帧。控制有效但 `|heading|>60°` 的分别为 28 张和 43 帧。这个数只标记极端拟合输出，不等于已确认错识别数量。

旧控制器在本重放中，连续无效累计 `lost_s>=0.2 s` 后仍输出运动的帧为 0。因此“丢线后 0.2 秒内停止旧指令”是已有修复的性质，不能把它当成 P1 detector 新增的实拍收益。

## 结论边界

这些资料没有逐帧车道中心/真实航向标注，也没有对应的物理位姿真值。**有效帧更多、误差绝对值更小、翻转更少都不能直接解释为准确率改善。** 新旧帧是否在真实车道上，需要看原图与候选，并在实车上核对。

四段录像拍摄于 2026-09-19，早于最新 loss 记录；有价值但不能代表最近模型、视觉方法、命令参数或走路闭环。新录像缺失，无法证明 P1 能让当前策略正确执行。处理耗时来自 Windows 本机 CPU，不能当作 Jetson 的实时性能指标。

使用真实 FPS 的 dt，可以检验本次重放传入的时间单位正确；仍按帧计数的 startup、红条确认、部分抖动历史等机制并未因此全部变成时间尺度，不能宣称整个 detector 对任意 FPS 完全不变。

## 最终前后结果

790 帧全部一一配对；完整输入、相机配置、控制器参数以及逐帧 FPS / dt / 分辨率 / 时间一致。

| 量 | 219 张独立 still：前 → 后 | 571 帧连续视频：前 → 后 |
|---|---:|---:|
| 控制可接受的当前观测 | 206 → 173 | 545 → 518 |
| detector 自评底锁有效 | 45 → 72 | 55 → 199 |
| 控制有效且 `|heading|>60°` | 28 → 9 | 43 → 2 |
| 无效底锁仍参与融合 | 30 → **0** | 150 → **0** |
| 新 detector 标无效但被控制当有效 | 不适用 → **0** | 不适用 → **0** |
| 连续丢线达到 0.2 s 后仍运动 | 0 → **0** | 0 → **0** |
| 新观测 stale 后仍运动 | 不适用 → **0** | 不适用 → **0** |
| near 小于 2 px、可信 heading 大于 8° | 不适用 → 4 | 不适用 → 8 |

P1 有 168 张 still / 435 视频帧提供可信 heading，117 张 still / 298 视频帧提供可信 preview。它们只是新合同自评的观测，不是真值标签。四段视频有效帧分别从 132/135/160/118 变为 131/121/153/113；质量门确实会牺牲部分可用率。

上述数据支持“无效锁不再混入、无效/过期观测不再伪装成新测量、near 接近零也不必抹掉可信 heading/preview”的实现性质。**它们不能支持‘实车巡线已解决’。** 极端角度变少部分来自不再给单边/不可信点拟合 heading，不能解释为已证明角度更准确。

视频相邻有效帧的 heading 符号翻转（两侧均超过 2°）从 45 次变为 11 次；near 翻转（超过 2 px）从 18 次变为 19 次；fused 翻转（超过 1 cm）从 0 次变为 1 次。这些量也受有效帧筛选和零值影响，只是输出行为描述，不是抖动真值或误差评价。

仍无效但在 0.2 s 淡出窗口内输出运动的帧，视频前后为 26 → 50；新质量门制造了更多短失效段，原有有限淡出仍在运行。超过期限和 stale 后的运动均为 0，不能把窗口内淡出误报成长时间续旧指令。

单张 still 的非零转向从 1 张变为 65 张，**不应据此判断假转向暴增**：旧版每张初始 EMA=0、首次只更新一部分；新版首次可信帧直接 seed 当前厘米观测。两者都是人为重新初始化的诊断场景，历史车上已经积累的滤波状态没有被复原。连续视频非零转向帧为 89 → 94，才保留各自的时序机制。

主机处理耗时中位数：still 43.74 → 39.54 ms，video 52.11 → 54.78 ms。完整过程含 OpenCV 与可视化；这不是受控 Jetson 性能实验，也不能用于认定部署能达到 20 Hz。

## 六帧人工检查与剩余反例

已查看 `inspection_01` 至 `inspection_06` 的原图与新旧鸟瞰：

1. 偏心画面 `loss_dump_2/010_04_pair1.00_conf0.00`：near 约 −94 px，新版不因偏心直接否定底锁。原图两条赛道边界可见；这支持解除“偏心即不可信”的语义，但不能单张证明真实横向厘米数。
2. `loss_dump/004_03_pair0.00_conf0.60`：清晰弯道只见单边，新 fresh detector 拒绝没有近期实测宽度支持的推断。可以减少无依据推断，也可能在真实单边路段更早失效；实车能否连续通过尚未验证。
3. `loss_dump_2/004_02_pair1.00_conf0.88`：主要来自中带，旧历史混合和新独立几何路径给出不同 near。不能把 fused 变大或变小直接判优。
4. `loss_dump_2/006_01_pair0.00_conf0.29`：旧 heading −75.4°、新 +56.2°，原图包含家具与弯道。剔除混入点改变了符号；没有姿态/轨迹真值，不给出“新符号已正确”的结论。
5. `loss_dump_3/007_01_pair1.00_conf0.96`：near 约 +1 px，但 heading 约 +53.5°，新 preview 不再因为 near 接近零而被比例夹成零。原图有明显运动模糊和弯道；机制生效不代表这个角度已经校准。
6. **明确保留的关联反例**：`loss_dump_2/004_02_pair0.00_conf0.30`。新版仍给 near≈+60.27 px、heading≈+76.41°、q≈0.266、有效=True。真赛道黑边在原图左下；拟合点经 `M_inv` 回投后落在木地板、椅腿/显示器底座区域，未落在真实赛道边界上。

第 6 帧两带接受了 5/8 和 8/8 个扫描点，**所有点的模式都是 `mode=3`，即原始灰度质心双凹陷 fallback**，没有阈值 run 真配对的 mode=2 点。扫描覆盖修复没有错误地放行稀疏分母，但几何一致的背景凹陷仍可被当成车道。源码中的“paired”在这里只证明找到了两个亮度凹陷，不证明它们属于赛道。

轻量来源抽查：六张人工候选里 5 张当前有效，其中 **3/5 的 near 只靠模式 3**；每段视频前 10 帧连续重放，共 40 帧全部当前有效，其中 **4/40 的 near 只靠模式 3**。抽样重放逐帧核对有效性和 near 与完整 final CSV 一致，没有用孤立视频抽帧代替历史状态。这是有选择偏差的样本（still 特意选变化/风险，视频仅起始 0.5 s），**不能外推为 173 张有效 still / 518 帧有效视频的总体比例**。其他样本仍依赖真阈值配对或混合来源；一个反例不足以支持禁用整个模式 3。

这份定位依据包括原图、接受的候选数组、每行模式和位置、原 IPM 的逆投影；仍未给全数据人工标注，也没有测出当帧真实俯角。非地面物体在 IPM 下被强行当成地面，以及姿态/安装角误差，都可能加剧问题。仅加严 q、宽度 CV 或拟合残差，会连带损失真正模糊的赛道，不能修复这个语义错误。

## 下一项可行方案

P1 完成了质量、一致性、时间和观测/控制合同的修复。下一项应是 **fallback 的身份与独立支持条件**：

- 模式 3 保留来源标记，不与阈值真配对无区别地共同给“可信 pair”背书。
- fallback 应需要近期独立真 pair 支持和跨帧边界延续，不能由自身连续 fallback 自我确认。
- 将候选与真实赛道区域/边界连续性关联，排除家具与非地面区域；用这帧和清晰/模糊真赛道样本同时验证。

本次不对单个反例调阈值，也不一刀切关闭模式 3。没有实车连接，仍无法证明改完后模型会按照给定速度和 wz 执行，或证明当前闭环能完成整圈。
