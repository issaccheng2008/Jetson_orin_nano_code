# 视觉转向窗口与丢线配置

在 Jetson 的 `config/button_start.env` 中添加或修改：

```bash
STEERING_COMMAND_WINDOW_S=0.5
STEERING_COMMAND_MEDIAN=lower
STEERING_LOSS_FALLBACK_WZ=0.3
```

- `STEERING_COMMAND_WINDOW_S`：统计窗口秒数，默认 0.5；0 关闭窗口。
- `STEERING_COMMAND_MEDIAN`：`lower` 下中位数，`upper` 上中位数；默认 lower。
- `STEERING_LOSS_FALLBACK_WZ`：无法使用近期转向历史时的备用角速度，单位 rad/s，范围 [-0.5, 0.5]。正数向左、负数向右、0 直行；仍服从 yaw-sign 和对应方向的转向幅值上限。默认 +0.3。

## 窗口如何选命令

每个正常巡线帧先完成现有图像处理、几何滤波、转向映射与离散化，再把最终的逐帧 WZ 放入当前窗口。每帧计一次；连接器和模型的重复读取不增加样本。

窗口不重叠。例如从 t=0 开始时，第一窗口为 [0, 0.5)，第二窗口为 [0.5, 1.0)。边界帧属于下一窗口。到边界后的第一张处理帧发送上一完整窗口的中位数，窗口之间保持该值。没有新视觉帧时不会凭空发送旧结果；原连接器/策略的失联保护继续生效。相机处理恢复时，如果已错过一整个窗口，会清除旧样本并重新起算。

有效帧的 WZ 按数值排序。奇数个样本选中间值。偶数个样本根据配置选中间两个值中的较小值或较大值，不取平均，因此结果仍是实际出现过的映射档位。例如只有 +0.1 和 +0.25 时，lower 为 +0.1，upper 为 +0.25。

所有丢线帧，包括过期观测、丢线历史补偿和丢线备用命令，都不参与中位数。有有效样本时，即使最后几帧丢线，也用有效样本的中位数。整个窗口都没有有效样本时，用现有控制器最新的丢线补偿：有可用近期历史则沿用历史，历史不可用或连续丢线达到 STEERING_LOSS_MAX_S 后用备用 WZ。

刚启动或停车恢复时，第一条正常巡线命令立即生效，并开始新窗口。按钮/二维码门控、图卡停车、人工停止和明确的启动序列立即生效并清除窗口，不等待中位数。

视觉端继续逐帧发送同一保持值以维持通信和图卡事件，不是每 0.5 秒只发送一个 UDP 数据包。0.5 秒控制的是正常巡线转向目标的更新。

## 策略进程的保持设置

通过按钮脚本自动启动策略时，启用视觉窗口会自动把策略入口的旧 command-min-hold-s 设为 0，避免把新中位数再延迟一次。此时旧配置 COMMAND_MIN_HOLD_S 即使是 0.5，也不再叠加保持。

手动启动策略 C 时，请同时使用 `--command-min-hold-s 0`。关闭视觉窗口时，自动启动策略仍沿用 COMMAND_MIN_HOLD_S。

## Jetson 更新与检查

```bash
cd ~/jetson_orin_code
git fetch origin
git switch policy49flitter
git pull --ff-only
nano config/button_start.env
bash scripts/run_button_vision.sh --dry-run
```

已有的 config/button_start.env 不会被 git 覆盖。未添加新配置项时也会使用上述默认值；可按需要把这三行加到现有文件，保留其 Python、串口、模型、相机与映射表设置。配置修改后需要重启视觉程序才能生效。

逐帧日志保留 `steering_frame_wz`（窗口前的逐帧输出）和 `steering_applied_wz`（窗口后实际发送值），以及窗口有效/忽略样本数和选择理由，便于核对丢线是否被排除。
