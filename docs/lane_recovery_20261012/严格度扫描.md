# 巡线接纳门槛：同帧阈值与仅方向兜底对照（2026-10-13 修正）

## 结论

修正版比较 **0/25/50/75/100% × 有/无仅方向兜底，共十组**。所有组都保留同一个连续模式，百分比只改变数值阈值；仅方向是独立开关。旧版在 100% 切换整个算法模式，混入了其他因素，不能作为单纯阈值比较，本轮撤销这个切换。

有仅方向时五档都只有 1 帧 `LOST`；无仅方向时，失效帧数依次为 134、98、70、67、132。未通过双边的帧仍会尝试单边；再失败时，只有开启组能进入 `VISIBLE_ONLY`。后者只有线的方向，**没有可信的赛道中心位置**，不能算作双边或单边路径。

这是一项接纳率对照，没有逐帧赛道真值，不能由接纳数推断走得更准。50% 和 75% 的单边位置数反而比 0% 多，说明这几个百分比不是单调的“去掉坏帧”旋钮。

## 比较方式

- 录像：2026-10-12 `test_120221_007796_2d456e27/video/camera_commands.avi`；SHA-256 `bc20d535a90dc51ffcfc1273808109df7b75d35cb5048654e25e23081d6800bb`。
- 852 个录像帧按 `frames.jsonl` 的 `source_frame` 去重后为 **466 个不同源帧**，其中录像命令 `vx>0` 的 **327 帧**另列一表。
- 只取录像左侧鸟瞰原图 `(0,0,480,358)`，缩回算法栅格；沿用同一 `contrast` 二值、LUT、标定、代码默认 12 cm 缺口补线和扫描距离。已是鸟瞰图，不再做一次 IPM。这个回放设置不一定等于当时板子的配置。

## 为什么中间值没有按预期增加 LOST

门槛是逐级尝试的：双边拟合失败后，会试单边拟合；单边失败后，开启组还允许只取可见线方向。严格度变大使一部分帧从 BOTH 改判为 RIGHT_ONLY，未必拒绝。较窄的关联搜索范围也可能消除多候选歧义，增加单边接纳。因此无仅方向组的失效数也不必随严格度单调增加；0% 中有 126 帧是身份歧义，并不意味着 126 张图都没有清楚的线。

旧版整个 `strict` 模式的 234 双边、56 单边、176 失效另存为 `strictness_sweep/reference_strict_mode/summary.json`，仅作历史参考，**不属于本轮十组阈值实验**。

当前录像缺少人工标注的“真实左右边界、中心位置、方向”逐帧真值。下一步若要选比赛档位，应在同一批关键帧标出这三项，分别统计错线、位置偏差、方向偏差及 `VISIBLE_ONLY` 接管的风险；再单独决定哪些方向兜底帧允许进入控制。不能仅靠减少 `LOST` 或增加 BOTH 选档。保持默认 0%，直到完成该核对。

## 复现与文件

按钮配置中的两个独立变量：

```bash
LANE_OBSERVATION_MODE=continuous
LANE_STRICTNESS_PCT=50
LANE_VISIBLE_DIRECTION_FALLBACK=1 # 1 开启；0 只关闭仅方向，不关闭单边路径
```

默认仍为 0% 且开启仅方向。手动入口分别用 `--lane-visible-direction-fallback` 和 `--no-lane-visible-direction-fallback`。任何百分比都显示 `effective=continuous`；需要整个原严格模式时另用 `LANE_OBSERVATION_MODE=strict`，它属于不同算法条件。

```bash
PYTHONPATH=/tmp/robocup_photo_deps python scripts/replay_lane_recovery.py \
  /tmp/nano_loss_audit/test_120221_007796_2d456e27/video/camera_commands.avi \
  docs/lane_recovery_20261012/strictness_sweep/pct_025 \
  --code-root "$PWD" --mode continuous --strictness-pct 25 \
  --gap-fill --visible-direction-fallback --no-save-masks
```

关闭组把最后参数改为 `--no-visible-direction-fallback`，输出路径改为 `strictness_sweep/without_visible_direction/pct_025`；其他四档只改百分比和输出目录。

`strictness_sweep/pct_*` 是开启组，`strictness_sweep/without_visible_direction/pct_*` 是关闭组。每档的 `summary.json`、`frames.jsonl` 和同帧总表 `same_frame_modes.csv` 可按源帧查状态，JSON 中同时记录扫描层拒绝原因。71 项相关离线测试通过，覆盖五档的实际图像仅方向接管及独立开关；尚未实机验证。

录像经过压缩、缩放和原录制流程处理；离线重放不是原始 USB 帧，也没有人工几何真值或实车轨迹验证。并行离线回放中的 `process_ms` 不能用来推断 Nano 实时性能。
