# 命令时序实验

当前分支：`policy49-exp-no-hold`。两个独立实验最初从按钮分支的 `ce79df7` 创建，均已同步按钮基准 `f58ac0d`；本无保持分支另外同步了 `eb7e8ee` 的低帧率分段确认修正、诊断和统计工具，快释放分支尚未同步这次修正。方案一：B/C 正常命令最短保持时间为 0；原视觉滤波、半秒趋势窗口及预测长度保留。

| 分支 | B：heading/segments | C：实际步行模型输入 |
|---|---|---|
| policy49-exp-no-hold | 有效视觉决策不再受正常最短保持时间阻挡 | 收到有效请求即可应用，不再等待半秒 |
| policy49-exp-fast-release | 同方向降档或归零可提前；升档、换向、vx 变化仍等待 | vx/vy 不变、yaw 同号且幅度减小时可提前；其他正常变化保持半秒 |

## 试跑

先停止正在运行的 A/B/C，再切换分支。两次实验保持同一套模型、速度、摄像机、档位、容忍度和启动参数；只切分支，不同时调参。

```bash
cd ~/jetson_orin_code
git fetch origin
git switch policy49-exp-no-hold
git pull --ff-only
```

原按钮启动配置和安装脚本可以继续使用，实验不需要新参数。此次同步包含按钮基准的服务安装修复；若此前尚未应用该修复，请按[按钮自启动说明](button_autostart.md)重跑安装脚本，已有配置保留。之后在两实验分支间切换只需停止并重启进程，无需反复安装服务。若已有本地分支，以上命令更新它；首次切换时 Git 会从同名远端创建跟踪分支。

按钮自启动现支持配置转向模式：在 `config/button_start.env` 中设置 `WZ_MODE=heading` 或 `WZ_MODE=segments`；旧配置缺少该项时默认 heading。模式切换后停止并重启进程即可，无需重装服务；可用 `bash scripts/run_button_vision.sh --dry-run` 检查实际参数。两次试跑使用相同模式，本实验对 heading 和 segments 均生效。若此前手动使用 segments，就在两次试跑中都保留 `--wz-mode segments`。手动启动时，A/B/C 都从同一分支目录运行；按钮模式自动启动的 C 也读取当前分支代码。不要另开一份 C。

完整按钮命令、PC2 和灯的流程见[当前上机说明](../new_vision/机器人上机命令与参数_当前版.md)。模型仍使用该基准的 `policy_49_max.onnx` 和 `policy-one-foot-standing_old.onnx`；没有加入 IMU 决策或单次电机响应标定。

## 方案边界

方案一取消的是正常命令保持，不是视觉滤波。分段仍需连续 3 帧确认；新鲜合格观测的帧间隔不超过 0.5 秒可连续确认，观测过期检查不变。heading 的中值滤波、0.5 秒趋势历史和0.5 秒预测长度保留。有效新观测不一定每帧产生新档位。低帧率修正没有恢复正常命令最短保持，详见[转弯占空比分析与测试方案](转弯占空比分析与测试方案.md)。

方案二示例：`+0.43 -> +0.37`、`+0.37 -> 0` 可以提前；`+0.37 -> +0.43`、`+0.37 -> -0.3` 仍等待。右转镜像适用。每次实际降档/归零都会重新开始半秒计时，因此不能用先归零再反向来绕过限制。反向请求经过原有中值滤波可能先得到零：允许先归零，相反方向仍需等待。非零直行 trim 若跨过 yaw 零点，按换向处理。

两版沿用原有异常处理：全零停车、图卡/直立/单脚接管可以立即打断；丢失或陈旧几何也保留原来的清 yaw、清确认和恢复路径。普通归零与这些异常退出不同，不能用正常保持规则推断异常恢复行为。

连接器沿用 `command_mode=held` 的直接透传，50 Hz 保活不变；该标记用于绕过连接器渐变，不代表本分支还有强制的半秒发送间隔。C 的诊断 `cmd_vx/cmd_wz` 和观察量 `vx/wz` 是实际应用值，`requested_cmd_*` 是应用前请求；方案二 B 的 `steering_reason=early_yaw_release` 标记提前释放。

## 验证

2026-10-08 同步低帧率修正后的本分支回归：视觉/按钮/UDP 等 319 项、策略部署 168 项全部通过，无跳过。新增默认无保持分段回归在修正前以 `1 != 2` 失败，修正后通过；确认连续三帧后仍 `min_hold_s=0`、`turn_left=0`。相对 `2835c0f` 的 `heading_steering.py`、`walking_command_hold.py`、`main.py` 和 connector 未改，保留实验时序。此前的验证记录如下：

- 基准视觉、按钮及模型保持测试：305 项、758 个子测试通过。
- 新实验用例在原基准出现预期失败，再分别通过。
- 本分支完整视觉及策略部署回归：470 项测试、869 个子测试通过；Windows 缺少 Bash，3 项按钮脚本测试自动跳过；原有依赖 Linux tee 的子进程测试排除 1 项。
- 真实本机 UDP 测试贯通：分段控制 -> B 发布 -> 连接器处理/透传 -> C 收包/时序处理 -> 49 维强化学习观察输入，验证转向在半秒内释放。摄像机输入使用已知几何，串口/模型推理用测试替身；未连接机器人。
- 验证左右方向、升档/反向限制、原严格策略显式配置、时间异常、丢线、停车和接管。独立审查未发现阻塞问题。
- 改动源码编译通过；提交前执行 Git 差异检查。

这只证明软件时序符合方案，不能证明实车更稳。实车建议与原按钮分支交替跑同一处弯道，多次比较出弯偏移/越界、入弯是否不足、指令切换次数和步态稳定性。
