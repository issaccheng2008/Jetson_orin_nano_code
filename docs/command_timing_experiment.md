# 命令时序实验

当前分支：`policy49-exp-fast-release`。两个独立实验都从 `policy49-button-test` 的 `ce79df70e8790467e8f85d841abb86ccb6762d83` 出发，互不叠加。方案二：正常升档、换向和线速度变化保持至少 0.5 秒；同方向降档/归零在 vx/vy 不变时可提前执行，每次实际变化重新计时。

| 分支 | B：heading/segments | C：实际步行模型输入 |
|---|---|---|
| policy49-exp-no-hold | 有效视觉决策不再受正常最短保持时间阻挡 | 收到有效请求即可应用，不再等待半秒 |
| policy49-exp-fast-release | 同方向降档或归零可提前；升档、换向、vx 变化仍等待 | vx/vy 不变、yaw 同号且幅度减小时可提前；其他正常变化保持半秒 |

## 试跑

先停止正在运行的 A/B/C，再切换分支。两次实验保持同一套模型、速度、摄像机、档位、容忍度和启动参数；只切分支，不同时调参。

```bash
cd ~/jetson_orin_code
git fetch origin
git switch policy49-exp-fast-release
git pull --ff-only
```

原按钮启动配置和安装脚本可以继续使用，不需要新参数或再次安装服务。若已有本地分支，以上命令更新它；首次切换时 Git 会从同名远端创建跟踪分支。

原自启动脚本继续使用 heading 模式；本实验对 heading 和 segments 均生效。若此前手动使用 segments，就在两次试跑中都保留 `--wz-mode segments`。手动启动时，A/B/C 都从同一分支目录运行；按钮模式自动启动的 C 也读取当前分支代码。不要另开一份 C。

完整按钮命令、PC2 和灯的流程见[当前上机说明](../new_vision/机器人上机命令与参数_当前版.md)。模型仍使用该基准的 `policy_49_max.onnx` 和 `policy-one-foot-standing_old.onnx`；没有加入 IMU 决策或单次电机响应标定。

## 方案边界

方案一取消的是正常命令保持，不是视觉滤波。分段仍需连续 3 帧确认；heading 的中值滤波、0.5 秒趋势历史和0.5 秒预测长度保留。有效新观测不一定每帧产生新档位。

方案二示例：`+0.43 -> +0.37`、`+0.37 -> 0` 可以提前；`+0.37 -> +0.43`、`+0.37 -> -0.3` 仍等待。右转镜像适用。每次实际降档/归零都会重新开始半秒计时，因此不能用先归零再反向来绕过限制。反向请求经过原有中值滤波可能先得到零：允许先归零，相反方向仍需等待。非零直行 trim 若跨过 yaw 零点，按换向处理。

两版沿用原有异常处理：全零停车、图卡/直立/单脚接管可以立即打断；丢失或陈旧几何也保留原来的清 yaw、清确认和恢复路径。普通归零与这些异常退出不同，不能用正常保持规则推断异常恢复行为。

连接器沿用 `command_mode=held` 的直接透传，50 Hz 保活不变；该标记用于绕过连接器渐变，不代表本分支还有强制的半秒发送间隔。C 的诊断 `cmd_vx/cmd_wz` 和观察量 `vx/wz` 是实际应用值，`requested_cmd_*` 是应用前请求；方案二 B 的 `steering_reason=early_yaw_release` 标记提前释放。

## 验证

- 基准视觉、按钮及模型保持测试：305 项、758 个子测试通过。
- 新实验用例在原基准出现预期失败，再分别通过。
- 本分支完整视觉及策略部署回归：470 项测试、869 个子测试通过；原有依赖 Linux tee 的子进程测试因 Windows 环境排除 1 项。
- 真实本机 UDP 测试贯通：分段控制 -> B 发布 -> 连接器处理/透传 -> C 收包/时序处理 -> 49 维强化学习观察输入，验证转向在半秒内释放。摄像机输入使用已知几何，串口/模型推理用测试替身；未连接机器人。
- 验证左右方向、升档/反向限制、原严格策略显式配置、时间异常、丢线、停车和接管。独立审查未发现阻塞问题。
- 改动源码编译通过；提交前执行 Git 差异检查。

这只证明软件时序符合方案，不能证明实车更稳。实车建议与原按钮分支交替跑同一处弯道，多次比较出弯偏移/越界、入弯是否不足、指令切换次数和步态稳定性。
