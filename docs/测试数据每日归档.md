# 测试数据每日归档

记录结束后，可用 [测试数据裁剪与绘图](测试数据裁剪与绘图.md) 自动截取启动后的数据并生成两张图。

按钮自启动和 `bash scripts/run_button_vision.sh` 都自动记录，无须新增配置。每次启动视觉程序创建一次测试目录；等待按钮、运行和停止前的视觉帧属于同一次测试。再次重启视觉创建新目录。日期使用 Jetson 本地时间，不覆盖旧数据。

```text
records/tests/
  2026-10-09/
    test_时间_唯一编号/
      recording_manifest.json
      video/camera_commands.avi
      video/frames.jsonl
      video/manifest.json
      vision/run_.../line_frames.jsonl
      vision/run_.../run_manifest.json
      control/control_trace_....csv
      control/control_trace_....manifest.json
      motor_positions/motor_positions_....csv
      main_....log
      loss/run_.../...
      shape/run_.../...
```

`RECORDS_DIR` 决定 records 的位置，可以继续在 `config/button_start.env` 修改。失线和图卡文件只有发生相应事件时才有内容；未按按钮启动步态时，没有执行与 IMU 数据文件。

## 摄像头录像与方向箭头

按钮启动默认开启录像，等待按钮和运动过程都记录。在本次测试目录的 `video/camera_commands.avi` 中查看巡线检测器当前帧的最终鸟瞰二值图。直接复用 `debug["binary"]`，包含当前预处理模式下的阈值、形态学与连通域筛选结果；白色为候选轨道、黑色为背景，不重新处理原始画面。完整图像保留在上方，方向标注放在下方，不遮挡图像。

- 左侧 `VISION` 蓝色箭头：本帧视觉识别、滤波和选档后发给 connector 的目标方向；位于 connector 的 WZ_BIAS 和步态最短保持之前。
- 右侧 `ROBOT CMD` 蓝色箭头：步态经过最短保持、停车和动作接管处理后，实际用于生成并发送关节目标的 VX/WZ。来自步态反馈，不在视觉侧重新模拟半秒计时。因此保持期内两个箭头可能不同。
- 正 WZ 指向左、负 WZ 指向右、WZ=0 直行。箭头倾斜程度只是指令大小的符号，不是预测轨迹或测得的实机转角。
- 红色箭头：视觉观测无效、过期、丢线或进入失线历史转向。即使短时仍保持转弯指令，箭头也会变红。
- 停车：显示 STOP 和同颜色叉号，不画前进箭头。
- 每个方向显示自己的 VX/WZ，右侧同时显示模式和保持剩余时间。尚未启动步态、反馈超过 0.5 秒、姿态反馈端口关闭时显示 UNKNOWN，不使用视觉值冒充实际值。电机未使能时显示 MOTORS OFF，写入未确认时显示 UNKNOWN (not sent)。动作接管时没有行走速度，显示 STOP 和当前动作模式。

实际指令复用 UDP 5007 姿态通道：通常每 0.1 秒回传，指令/模式改变时额外立即回传；接收后的指令不做姿态低通。视频在下一次摄像头处理完成时显示最新反馈，仍受视觉帧率和回放重采样影响。启用视觉中位数窗口时，0.5 秒是转向样本统计窗口，自动启动的策略不叠加旧最短保持；步态仍按约 50 Hz 发送关节目标。机器人收到的是关节目标而非 VX/WZ，右侧方向是对应模型输入，不代表实机已达到这个角速度。

视频因相机暂停而重复画面时，每个输出帧仍按时间检查实际反馈：超过半秒变 UNKNOWN，索引变 null，不把旧箭头延长为当前实际指令。显示的保持剩余时间为最近反馈中的值，不在录像线程重新生成控制命令。

升级后需重启视觉与其自动启动的步态，新测试才有双箭头；旧视频不会被改写。保持默认 `--attitude-port 5007`，关闭该通道时实际方向为 UNKNOWN。无需重新烧录下位机。

在 `config/button_start.env` 添加或修改：

```bash
RECORD_VIDEO=1
VIDEO_SOURCE=binary # 改为 camera 即可恢复原始摄像头画面
VIDEO_FPS=10
VIDEO_WIDTH=960
```

`VIDEO_SOURCE=binary` 为默认值，旧配置未添加此项也会记录二值图；切换为 `camera` 后重启视觉程序即可恢复原始画面。视频路径、双方向箭头、日志与旧录像保持兼容。MJPG 压缩可能使像素偏离精确的 0/255，记录内容仍来自检测器的最终二值掩码。`RECORD_VIDEO=0` 关闭。`VIDEO_WIDTH` 只缩小录像，不更改识别分辨率。`VIDEO_FPS` 是回放帧率，不会提高摄像头识别或指令输出频率；低帧率的采样会按时间重复画面，避免录像比实机播放更快。每个新采样对齐到下一个视频时间点，延迟不超过 1/VIDEO_FPS 秒。

后台编码队列最多两张，编码慢时丢录像采样，巡线不等待编码；`video/manifest.json` 记录丢采样数量与错误。`frames.jsonl` 为每个编码帧保存源画面编号、发送时间、视觉 VX/WZ、失线状态，以及 executed_command（实际 VX/VY/WZ、步态时间、步号、模式、串口写入状态），可与视觉/控制日志对齐。执行反馈缺失时该字段为 null。编码失败会打印 `[video] recording disabled`，不改变控制指令。正常退出给后台两秒排空，超过预算则截断末尾补帧，等待当前编码调用返回后关闭 AVI 和索引，并在 manifest 标记 truncated；强制 kill 或掉电可能导致末尾录像不完整。

更新代码后重启视觉服务即可，新测试开始生成视频；旧测试不补录像。已有配置不含上述字段时默认启用。手动运行使用 `--recording-root`，默认 `--video-source binary`，可用 `--video-source camera` 恢复原始画面，并可加 `--video-fps 5 --video-width 640` 或 `--no-record-video`。如实机测得录像对帧率影响明显，先降到 640 宽、5 FPS 对照；后台编码仍会占用 CPU，不承诺完全没有开销。

## 四项数据在哪里

| 数据 | 文件与字段 |
|---|---|
| 视觉识别的机身相对赛道偏转角 | JSONL 的 `body_track_deviation_deg`，单位度；`body_track_deviation_valid` 为 false 时不可当作有效角度。原始字段 `measurement.heading_control_deg` 同时保留 |
| 视觉发出的指令 | 同一 JSONL 的 `vx`、`wz`，单位 m/s、rad/s；滤波前后值与判断原因在 `measurement` |
| 上位机实际用于策略的指令、发送角度 | control CSV 的 `requested_cmd_wz` 是请求；`cmd_wz` 是保持等处理后的模型输入。`motor_send_argument_*` 是最终发送给下位机的各关节目标角，`received_q_packet_*` 是反馈关节角，单位 rad |
| IMU | 同一 control CSV 的 `received_accel_x/y/z`（m/s²）、`received_gyro_x/y/z`（rad/s）与 `received_orientation_w/x/y/z`（四元数） |

`cmd_wz` 是角速度指令，不代表实机已达到该角速度；关节目标角也不代表机身实际偏转角。IMU/关节反馈在步态控制循环中随状态采样记录，不是另行保存所有 USB 原始包。

对齐视觉与执行数据时，使用 `host_time_ns / 1000000000` 与 CSV 的 `host_unix_s`，都是同一 Jetson 的 Unix 时间。不要用文件修改时间代替采样时间。

## 更新与查看

```bash
cd ~/jetson_orin_code
git pull --ff-only
sudo systemctl restart humanoid-button-vision.service
sudo journalctl -u humanoid-button-vision.service -f -o cat
```

启动日志里的 `[recording] test directory:` 会显示此次测试的完整路径。策略实时文本日志仍可使用 `tail -f records/main_live.log` 查看。

查看当天测试目录（默认 RECORDS_DIR）：

```bash
ls -td records/tests/$(date +%F)/test_*
```

完整导出一次测试：把下面的目录名替换为启动日志显示的名字。

```bash
tar -czf test_analysis.tar.gz -C records/tests/2026-10-09 test_实际目录名
```

若直接使用原来的一长串 `python ... run_policy_vision.py` 命令，在末尾加 `--recording-root "$PWD/records/tests"`。该参数统一管理所有记录目录，优先于单独的 `--line-log-dir`、`--dump-on-loss`、`--shape-dump`。不使用它时，旧命令的独立记录路径仍兼容。

## 滤波回放

```bash
python new_vision/jetson/replay_steering_filter.py \
  records/tests/2026-10-09/test_实际目录名/vision/run_实际目录名/line_frames.jsonl \
  --output-dir records/filter_replay
```

控制、IMU 和视觉无需再从几个独立 records 子目录猜测配对；直接导出整个测试目录即可。旧记录不会搬迁或删除。
