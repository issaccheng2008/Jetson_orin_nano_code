# 机器人上机命令与参数：当前版

适用范围：`policy49` 分支，视觉双闸启动，B 自动启动 C；核对日期 2026-10-08。以下 B 的巡线数值沿用 2026-10-07 的现场命令，**不是新推荐调参值**。旧版长文见[历史说明](机器人上机命令与参数.md)。

## 1. 三个进程与启动顺序

| 进程 | 工作 | 主要输入、输出 |
|---|---|---|
| A：`connector.py` | 收 B 的视觉命令，以 50 Hz 向 C 重发、限幅和限斜率 | B → UDP 5006；A → UDP 5005 |
| B：`run_policy_vision.py` | 相机巡线、图卡/二维码、起步门控，决定 `vx/wz` | 相机 → UDP 5006；接收 C 的机身姿态 UDP 5007 |
| C：`main.py` | 运行步行/单腿 ONNX，向 STM32 连续下发关节命令 | UDP 5005 → `/dev/ttyACM0` |

比赛双闸模式：先开 A，再开 B；B 识别首卡与二维码后自动启动 C，**无需手动开启第三份 C**。三个终端若都手动进入仓库，应使用同一分支并执行：

```bash
cd ~/jetson_orin_code
git branch --show-current
source .venv/bin/activate
mkdir -p records
```

`source` 只影响当前 shell。B 自动启动的 C 可由 `--start-policy-python` 明确指定解释器；先核对该解释器能导入模型运行依赖：

```bash
~/venvs/humanoid_policy/bin/python -c 'import sys, onnxruntime, serial; print(sys.executable, onnxruntime.__version__)'
```

2026-10-07 的板上检查曾确认此环境有 `onnxruntime 1.27.0`，另一个 `.venv` 则报缺包；以后以**当场自检**为准。若此命令失败，先确定实际可用的解释器，再修改下方 B 的 `--start-policy-python`。

### 终端 A：先启动连接器

```bash
connector_run_stamp=$(date +%Y%m%d_%H%M%S)
python -u connector.py --vision-port 5006 --policy-port 5005 \
  --max-vx-accel 1 --max-wz-accel 0 \
  2>&1 | tee "records/connector_${connector_run_stamp}.log" records/connector_live.log
```

### 终端 B：比赛双闸、自动启动 C

```bash
vision_run_stamp=$(date +%Y%m%d_%H%M%S)
python -u new_vision/jetson/run_policy_vision.py --camera 0 --headless \
  --start-gate both --start-policy-on-gate \
  --start-policy-python ~/venvs/humanoid_policy/bin/python \
  --start-policy-model "humanoid_jetson_deploy/policy_49_max.onnx" \
  --start-policy-one-foot-model "humanoid_jetson_deploy/policy-one-foot-standing_old.onnx" \
  --wz-mode heading --vx 0.2 --max-wz 0.5 --wz-step 0.3 \
  --heading-lookahead-cm 50 --heading-corridor-cm 5 \
  --heading-right-tolerance-deg 9 --heading-left-tolerance-deg 4 \
  --heading-full-scale-deg 15 --heading-left-wz 0.3 0.4 0.5 \
  --card-trigger-dist-cm 30 --shape-every 2 \
  --line-log-dir records/line_telemetry \
  --dump-on-loss "records/loss_${vision_run_stamp}" \
  --shape-dump "records/shape_${vision_run_stamp}" \
  2>&1 | tee "records/run_${vision_run_stamp}.log"
```

需收集前方多段赛道方向时，在 `2>&1` 前加 `--lane-fit-segments`：只增加观测日志，不改变控制输出。参见[弯道几何与分段观测验证](../docs/audit_2026-10-08/弯道几何与分段观测验证.md)。

需对照新边界追踪时，在 B 命令加 `--track-observe`。它从鸟瞰图的独立内外边界线段估计近处位置、实测范围内的目标与进出弯阶段；允许线条不平行、弯道不同心和短暂断线。**当前 `heading` 下它只记日志，不改变发给 A/C 的命令。**逐帧查看 `measurement.track_*` 与 `measurement.track_shadow_wz`。离线复查已有丢线图片：

```bash
python new_vision/scripts/replay_track_geometry.py records/loss_dump \
  --output /tmp/track_replay.csv
```

独立控制入口为 `--wz-mode track`，仅供短程试跑；它自动打开观测、沿用 0.5 秒保持，观测不可信时回退旧 `heading`。当前 216 张真机丢线帧回放中，新路径可用 131 帧，其中单边 29 帧；与旧方向估计有明显分歧的帧仍需核对原图，**未做实车验证，勿直接替换比赛命令**。若试跑该模式，必须将 `--wz-step` 设为 `0.5` 并明确 `--heading-left-wz 0.37 0.43 0.5`，否则命令中的 `0.3` 上限会裁掉弯道基础档。`--track-confirm-frames` 默认 3，可调连续确认帧数。详见[实现与离线证据](../docs/audit_2026-10-08/非理想赛道边界追踪与模糊图卡预警_实现记录.md)。

### 弯道分段控制试跑

将 B 命令中的 `--wz-mode heading` 改成 **`--wz-mode segments`**，即可让合格的分段观测参与实际转向；它会自动打开 `--lane-fit-segments`。A、C 使用上述程序和参数。原 `heading` 仍是默认模式，直接换回该值即可对照。

沿用原先手动 A、C 的 `vx=0.2` 实验入口时，B 命令如下：

```bash
python -u new_vision/jetson/run_policy_vision.py --camera 0 --headless \
  --wz-mode segments --vx 0.2 --card-trigger-dist-cm 30 \
  --line-log-dir records/line_telemetry
```

新模式在连续 3 帧可信后，取中/远段实际观测范围内、且不超过前视距离的目标点；近端锚定或段间连续性等检查失败时回退 `heading`。正常命令仍至少保持 0.5 秒，停车优先。每帧日志的顶层 `vx/wz` 是实际发送命令，`measurement.segment_shadow_wz` 是同帧原 `heading` 的对照计算。详见[分段控制接入与验收](../docs/audit_2026-10-08/分段控制接入与验收.md)。软件测试通过不等于实车弯道通过，需结合视频和实际轨迹做对照。

### 终端 C：手动模式才运行

以下命令用于**不开** `--start-policy-on-gate` 的实验。手动模式按 A → C → B 启动，并从 B 命令删去 `--start-gate both --start-policy-on-gate --start-policy-python ...`；这样起点首卡特殊策略也不会启用，别与比赛双闸模式混用。

```bash
policy_run_stamp=$(date +%Y%m%d_%H%M%S)
~/venvs/humanoid_policy/bin/python -u humanoid_jetson_deploy/main.py --policy walking \
  --model "humanoid_jetson_deploy/policy_49_max.onnx" \
  --one-foot-model "humanoid_jetson_deploy/policy-one-foot-standing_old.onnx" \
  --port /dev/ttyACM0 --command-source vision --udp-command-port 5005 \
  --step-cm 5 --diagnostic-log-dir records/control_diagnostics \
  --no-plot --max-seconds 1200 --enable-motors \
  2>&1 | tee "records/main_${policy_run_stamp}.log" records/main_live.log
```

B 自动启动 C 时，另加内部 `--startup-ready-file`，等 STM32 状态确认后才释放起步；默认行走模型是 `policy_49_max.onnx`，单脚站模型是 `policy-one-foot-standing_old.onnx`，步长默认 5 cm。B 可用 `--start-policy-model`、`--start-policy-one-foot-model`、`--start-policy-port`、`--start-policy-max-seconds` 分别改自动 C 的行走模型、单脚模型、串口、时长。**当前 B 没有转发 `--step-cm` 或 C 的关节限幅参数**；要改这些值，应采用手动 C 模式，或先给自动启动器增加参数并单独验证。

### 如何替换行走模型和单脚站模型

| 用途 | 当前默认文件（仓库根目录下） | B 自动启动 C 的参数 | 手动 C 的参数 |
|---|---|---|---|
| 行走、直走与转弯 | `humanoid_jetson_deploy/policy_49_max.onnx` | `--start-policy-model` | `--model` |
| 图卡 3/4 的单脚站动作 | `humanoid_jetson_deploy/policy-one-foot-standing_old.onnx` | `--start-policy-one-foot-model` | `--one-foot-model` |

将新 `.onnx` 文件放进 `humanoid_jetson_deploy/`，在上方 B 命令中修改对应模型参数后面的路径，再重启 B/C。两项参数独立：只改 `--start-policy-model` 就只替换行走模型；只改单脚参数就只替换单脚站模型。省略这两项时使用表中的默认文件。已有命令若显式写了旧模型路径，必须修改该路径，显式参数优先于默认值。

模型路径支持相对仓库根目录的路径或绝对路径；文件名有空格或括号时用双引号包住整个路径。手动启动 C 时，分别修改 `--model` 和 `--one-foot-model`。`--start-policy-python` 只选择 C 的 Python 环境，模型文件由上述两个模型参数选择。

替换的行走模型需匹配当前程序的 49 维观测、12 维动作；单脚站模型需匹配 46 维观测、12 维动作，并保持相同的观测含义、关节顺序与动作缩放。路径不存在时自动启动器会在启动 C 前报出缺失的模型文件；维度相同也不代表训练配置兼容，应核对模型来源。

## 2. 参数到底在哪一层生效

| 参数 | 所属进程 | 现场命令/默认 | 实际作用 |
|---|---|---|---|
| `--vx` | B | `0.1 m/s` | 发给策略的前进命令；不等于实测地面速度。C 命令行中的 `--vx` 只供 fixed 模式，视觉模式不取它。 |
| `--max-wz` | B | `0.5 rad/s` | B 的总转向上限。 |
| `--wz-step` | B | `0.3 rad/s` | heading 模式的**档位上限**。本命令写了左档 `0.3 0.4 0.5`，但有效左档仅 `+0.3`；默认右档 `0.3 0.5` 也只剩 `-0.3`；直行 `0`。 |
| `--heading-left-wz` / `--heading-right-wz` / `--heading-straight-wz` | B | 左 `0.3 0.4 0.5` / 右默认 `0.3 0.5` / 直行 `0` | 候选档位，受 `--wz-step`、左右上限共同筛选。想启用 `0.4/0.5`，需单独试 `--wz-step 0.5`。 |
| `--heading-lookahead-cm` | B | `50` | 用近处偏移与赛道方向算前方目标方位；当前多数时候并未直接观测到 50 cm 的中线。 |
| `--heading-corridor-cm` | B | `5` | 横向越靠近走廊边界，越强制采用至少最小转向档；缩小会更早纠偏。 |
| `--heading-right-tolerance-deg` / `--heading-left-tolerance-deg` | B | `9` / `4` | 目标方位的非对称直行容忍区；前者容忍机身朝右偏得更多。走廊仍可收紧实际容忍。 |
| `--heading-full-scale-deg` | B | `15` | 超过容忍边界后，目标方位再偏多少角度才达到完整需求；调小会更容易升档。 |
| `--card-trigger-dist-cm` | B | `30` | 后两张卡靠近后的停车触发距离；起点首卡走双闸特殊路径。 |
| `--shape-every` | B | `2` | 行走时每隔多少帧跑一次图卡检测，影响触发采样间隔。 |
| `--track-observe` | B | 关闭 | 只记录独立边界、目标与对照命令；现有 `heading` 输出不变。 |
| `--wz-mode track` / `--track-confirm-frames` | B | 不启用 / `3` | 显式试验新目标；连续可信后才控制转向，证据不足回退 `heading`。 |
| `--max-vx-accel` / `--max-wz-accel` | A | `1` / `0` | A 转发前的速度斜率上限；`wz` 为 0 表示关闭该斜率限制。 |
| `--step-cm` | C | 默认 `5` | 策略步距输入，独立于 B 的 `--vx`；**自动启动 C 目前只能用默认值**。 |
| `--max-target-speed-rad-s` / `--max-target-deviation-deg` | C | 默认 `3` / `10` | 模型关节目标的变化率上限、相对反馈角的窗口；设 0 分别关闭对应限制。自动 C 当前不转发这两个参数。 |
| `--joint-limit-margin-rad` | C | 默认 `0.05` | 绝对关节边界内缩量。 |

heading 模式正常行走命令每段至少保持 **0.5 秒**；停车和接管可以打断。`--wz-fire-cm`、`--wz-stop-cm`、`--wz-turn-s`、`--wz-gap-s` 等是旧离散模式参数，当前 heading 命令不靠它们选档。C 对模型输出的关节目标按“绝对边界 → 目标变化率 → 相对反馈窗口”处理，详见[上位机裁剪配置说明](../docs/audit_2026-10-04/上位机裁剪配置说明.md)。

## 3. 图卡、日志与快速检查

普通图卡停下后的投票窗口：`--card-stop-ms` 默认 3000 ms；STM32 完成低头动作并上报 DONE 后，再等 `--card-settle-ms` 默认 100 ms 开始投票；`--card-vote-frames` 默认 20，停留预算先到时按已有票数定案。`--card-tilt-ms` 默认 1800 ms 是没有 DONE 状态时的旧兼容等待。卡片动作 `--card-hold-ms` 默认 3000 ms。首卡双闸路径与后两张普通图卡路径不同，详见旧文档“起跑门控”一节。

模糊图卡的停车预警现用 cue 分数至少 `1.2`、最近 9 次检测至少 2 次命中且最近 3 次至少一次；之前为 `2.0` 和 3 次。未确认的远处 cue 只能给下一张卡重新武装，不能直接停车或参与六类图形投票。旧实拍运动视频对照中第四段首次确认约提前 12 视频帧；仍须用本次相机与地板背景日志核对误停。

| 日志 | 内容 |
|---|---|
| `records/run_<时间>.log` | B 视觉、图卡、起步闸；B 自动启动 C 时也能看到 C 的输出 |
| `records/connector_<时间>.log` / `records/connector_live.log` | A 转发状态与报错 |
| `records/main_<时间>.log` / `records/main_live.log` | C 模型、串口、报错；自动 C 由 B 创建，手动 C 由上方 `tee` 创建 |
| `records/line_telemetry/**/line_frames.jsonl` | B 每帧标量；加 `--lane-fit-segments` 或 `--track-observe` 后含对应几何和对照字段 |
| `records/control_diagnostics/` / `records/motor_positions/` | C 关节目标、反馈、IMU 等诊断 |

实时看 A、C：

```bash
tail -n 80 -F records/connector_live.log records/main_live.log
```

若 B 报 `policy Python cannot import onnxruntime`，先执行本页第 1 节的绝对路径自检；若 B 报 `policy exited ...`，看 B 打出的 C 最近 20 行及 `main_<时间>.log`。相机与串口设备号可能变化，启动前核对 `/dev/video*` 和 `/dev/ttyACM*`。任何改动均在 `records/` 中留下本趟命令、日志和模型版本，便于对比。
