# 偏左时左转收手

适用：`--wz-mode heading`。沿用现有启动命令，无新增终端参数。

## 工作机制

1. 从控制器认可的当前几何量读取近端偏移 `near`。正值表示赛道中心在相机右边，即机身相对赛道偏左；它是视觉估计，不是实测机身或脚的位置。
2. 连续两帧有效量测满足 `near >= 4 cm`，确认偏左。配对几何优先，原有有效单边几何兜底也可以提供量测。单帧尖峰不触发；量测失效、回到阈值以下、外部复位或停车会清除确认。
3. 当前正常命令的 **0.5 秒保持完整执行**。保持到期后，如果原算法还要左转，将该候选改成直行 `wz=0`，前进速度继续使用原有 `--vx`。
4. 仍确认偏左时不启动下一段左转。原算法若选择右转，照常执行；机身偏右时的左转恢复判定也保留。

该判断在几何左右方向上执行，然后才通过 `yaw_sign` 映射成线上命令，因此正负号配置不会反转这条规则。原有离散档位、预测减转、丢线处理和图卡接管继续执行。

## 代码和日志

- 实现：`new_vision/jetson/heading_steering.py`。
- 固定常量：`LEFT_OFFSET_RELEASE_CM = 4.0`、`LEFT_OFFSET_CONFIRM_FRAMES = 2`。本次不增加调参项；与角度容忍参数是不同的量。
- B 的 `line_frames.jsonl` / `measurement` 中增加 `steering_left_offset_confirmed` 和 `steering_left_offset_release_cm`。
- 保持到期后实际拦下左转时，`steering_decision = left_offset_release`；保持期间仍为 `steering_reason = minimum_hold`，此时确认偏左并不代表已经收手。
- C 的 `cmd_wz` 才是真正模型输入。现有 C 保持仍生效，B 收手时刻不一定就是 C 收手时刻。

## 验证与边界

回归覆盖：半秒到期前不提前收手、持续偏左不再启动左转、单帧抖动、有效单边量测、两种 `yaw_sign`、两侧恢复、丢线及外部停车后的确认清除。

使用 2026-10-04 三趟原始 B 日志进行固定输入回放，旧控制器完全复现记录命令：

| B 记录开始时间 | 帧数 | 本次改变的帧数 | 前进速度变化帧数 |
| --- | ---: | ---: | ---: |
| 16:03:11 | 732 | 6 | 0 |
| 16:04:51 | 120 | 0 | 0 |
| 16:05:25 | 394 | 0 | 0 |

改变的 6 帧均从左转改为直行。这里包含 B 完整记录，不能把 C 已失联后的 B 命令当成实际执行，也不能把固定输入回放当成新策略的实车轨迹。

最近两趟原先的弯道入口第一段左转没有被这条规则改变。它只解决“已稳定确认偏左还继续追加左转”，不能缩短第一段半秒，也不能保证消除全部入口过转。实际效果需下一趟实车确认。
